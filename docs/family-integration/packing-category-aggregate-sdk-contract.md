# U04-C3c2a — category aggregate SDK and owned queue contract

The C3c1 database remains unchanged. This packet adds its strict v3 client domain and authenticated five-RPC whitelist, an owned SDK cohort, handler/session and explicit retained-queue recovery. Native category drag, nonempty Delete and batch-restore controls stay gated; saved v1/v2/v3 packages and native markup/styles remain unchanged. Read the adjacent database contract for exact public signatures and relational rules.

`packingCategoryAggregateRpc` exposes only lane, observation, batch listing, execute and typed receipt RPCs. It uses the installed authenticated browser client, preserves service errors and never calls raw tables or falls back to a different protocol. The backend package's existing wildcard exports expose the two reviewed boundary/test additions; no dependency or package export change is needed.

The separate strict schema accepts version3/kind discriminants with complete nested v2 category facts, existing item facts, canonical UUIDs, safe integers, finite microsecond timestamps and byte/count limits. Scope, Trip, category, owner, sorted membership, lifecycle, batch count and complete category permutation are coupled. Labels remain raw data; empty, literal Other, prototype-like text and Unicode variants stay distinct. A virtual category/item key is not a UUID and fails before retention or effects. Old strict parsers and serialized bodies are not widened or rewritten; the retained union adds a new independent branch and `/trips/<UUID>/family/packing/category-aggregate-v3` URL.

Acknowledgment validation matches the exact original action, scope, target, operation and values. Order results preserve all unrelated category facts and change only appropriate ranks/revisions/timestamps. An unchanged sparse order is a true no-op. Batch results preserve exact child identity/content, bags, recipients, contributors and ordering, changing only allowed lifecycle/revision/timestamp facts. The original Trash batch key is immutable; deliberate restore has a distinct operation UUID. A historical acknowledgment is proof of commitment, not a current snapshot.

Reads validate the expected current identity, exact requested lane/category/lifecycle, complete owner-lane facts, unique UUID/rank ordering, member privacy and sorted relations. Deleted-batch lists distinguish original manifests from legacy empty dismissals, enforce counts, page size, paired cursors and descending timestamp/UUID order at microsecond precision. Empty legacy recovery remains a different v2 operation; there is no automatic fallback from an unknown v3 failure.

Receipts are `unknown|committed`, with explicit redaction and correctly paired result/null. A visible result must match its original envelope; a redacted committed receipt never authorizes replay. Current identity must match and root lifecycle cannot regress; the original result retains its historical root scope. The server enforces original-user/Person receipt ownership. Error mapping preserves denial, session expiry, conflicts, size and integrity errors without inventing success or a replacement operation.

`PackingCategoryAggregateCommandSession` captures the original envelope, active write-session owner, repository context/identity registry, native Trip, published layer, source and optional view lifetime. It rechecks these fences around waits, RPCs and queue effects. Concurrent submit coalesces; the packet is retained exactly before send under the existing queue lease. A lost reply keeps it unchanged. Explicit recovery inspects the authenticated typed receipt; unknown remains retained, while an explicit retry uses the same original operation and observations. Known visible/redacted commitment can remove only its exact unchanged queue row. Changed rows, account/Person/source/layer/logout/disposal and late replies cannot clear newer work. Background generic replay already holds all category-version routes; this new URL is covered without changing that rule.

Startup recovery works without a full planner snapshot. Existing planner-level receipt reconciliation also dispatches the new branch, preserving all earlier domains. Cross-domain UUID collisions leave the older valid original bytes intact. No queue schema version, parallel command store, optimistic native write or new offline authoring mode is introduced.

`PackingCategoryAggregateCohort` exposes owned lane/observation/batch reads and submission, while refreshing existing coupled v2 metadata separately after commitment. A newer generation/reset discards a slower result; snapshots are cloned and do not publish native/cache state. The normal planner owns this SDK cohort and resets it with its existing lifecycle. Native consumers must still compose and capture their exact filter/view lifetimes before activation in C3c2b.

The actual SDK verification uses only marked localhost125, synthetic Family/Trip data, real Auth/TOTP and PostgREST. Production/preview and hosted SQL/settings/billing are outside scope. No new browser/App/worker acceptance or image-download claim is made by this SDK-only packet; those remain requirements of the next native cutover.

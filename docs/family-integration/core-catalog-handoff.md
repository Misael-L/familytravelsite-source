# U04-F5 — native typed catalog journey acceptance

14 November 2026. Based on `98764f54dbcc7f84398787e8d17bf39301602062`, branch `codex/trek-v5.1.4-family-reconcile`. Local catalog acceptance is complete on schema136. This is not hosted/default-profile release acceptance, public publication, source-adoption approval or a preview update.

## Delivered

The native map category/search-area hook now reads bounded Family venue queries through the real application handler. Text search, autocomplete, selected detail, selected photo and enrichment use typed `catalog:<kind>:<uuid>` keys. Food, hotel, experience and geographical place identities stay distinct; each hit uses its own coordinates, never the related city's point. Archive state, valid coordinates, type codes, finite/wrapped bounds, deterministic caps and query/source/actor/Trip cancellation are enforced. Real empty results differ from API failures or unsupported categories. No external places provider is called.

Supported category mappings are restaurant, cafe, bar, hotel, sights, nature, activity and bakery. Museums are deliberately unavailable: the existing `CULTURAL_EXPERIENCES` lookup also contains non-museums, so assigning all of it to Museums would be false. Grocery/supermarket has no verified dedicated mapping. Both return explicit unavailable errors rather than fabricated empty success. Tours and other unsupported advanced features stay off. Native category chips/layout are unchanged; their existing error/retry state is used, not a new disabled-chip design.

Ready-v1 thumb/hero objects are selected from the current configured Supabase source. Missing/unready/foreign/original/transform URLs produce placeholders. Coordinates do not trigger provider photo enrichment. Native cached-photo credit explicitly says `Family Catalog · credit not recorded`, preventing TREK's default cached-photo caption from falsely naming Wikimedia Commons. It does not assert a creator or licence.

Native creation performs a current catalog read and retains the exact source kind/id in the existing observed transactional command. Unedited shared description/address/coordinates stay inherited; Trip notes and intentional overrides belong to the saved location. The catalog observation is frozen for an unresolved original, so lost replies retain their operation and payload. Saving the same venue again to the pool is refused with guidance to reuse its saved location; deliberate independently scheduled visits remain supported.

Unsupported removal of an inherited catalog image is refused until an explicit per-Trip override contract exists; the adapter cannot silently acknowledge an ignored edit.

Two real native integration mismatches were fixed without changing the copied layouts. Retained native callbacks now read current Family permission state, so a callback created before hydration can use a later Direct grant and refuses later revocation/staleness. Native5.1.4 POI forms explicitly spread `duration_minutes: undefined`; the adapter now accepts only that absent value. Actual unsupported durations still refuse the whole save. Regression inputs use the native opener and native form payload helper.

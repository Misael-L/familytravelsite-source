# Observed stay command contract v1

Exact SQL is the paired canonical migration 131. Public commands and context/history readers are authenticated only; the backend enforces original Family/person/Trip/session and Direct permissions. Public table writes and raw ledger/sequence/helper access are absent. This document refines the parent proposal for the new stay APIs only.

- Scope: exactly version 1, layer published, trip_id, family_id, user_id, person_id, session_id. Context generates all identities; the client must preserve them.
- Observation: exactly trip_revision, stay, candidate_location, candidate_booking. Existing stay is the complete130 projection; create has JSON null. Selected target projections bind their real current identities/revisions/facts.
- Save(p_trip_id uuid,p_stay_id uuid,p_operation_id uuid,p_scope jsonb,p_observation jsonb,p_changes jsonb): original observation and strict patch; create requires a new stay UUID plus location and independent civil dates.
- Link(p_trip_id uuid,p_stay_id uuid,p_operation_id uuid,p_scope jsonb,p_observation jsonb,p_reservation_id uuid): null unlinks. Selected booking must match candidate_booking in the original context. Current and selected rows are locked and compared.
- Trash/Restore use the same first five arguments. They preserve content, references and immutable history. Restore does not repair/relink foreign/deleted lodging behind the user's back.
- Receipt namespace: one immutable operation per Trip/actor/operation UUID across every stay action, exact request SHA256, original session and retained before/after images. No-op gets an acknowledgement without content revision growth. Reuse with a different body/action/identity conflicts. Receipt retry reauthorizes, then returns the historical acknowledgement without reapplying it.
- Results contain acknowledgement/read_current_required, committed identity/revisions, operation/action, changed, event_sequence and recorded_at. They contain no replacement record. A new Auth session cannot rebind an old request.
- Errors:22023 malformed fields/scope/bounds, PT409 stale context/original session or conflicting operation/concurrent claims,42501 denied current admission,0A000 unsupported layer/retained proposal/trashed edit,23514 invalid relational/clock/date/lodging combination,54000 admission/read/output limit. Unsupported compounds remain refused as a whole.
- History has keyset pagination with bigint before_sequence, limit 1–100/default 50, has_more and next_before_sequence; it excludes session/digest/internal result. Operational receipts persist in SQL recovery; portable Family export keeps the safe trip_stay_history projection under its original active-Trip scope.

One private immutable ledger intentionally fulfills both receipt and history storage. FK ownership is restrictive; a session FK is deliberately absent so ordinary Auth cleanup cannot destroy/block retained content. Atomic save/link/restore checks and their revisions/history succeed or roll back together. Parent Trash freezes new commands and replay. Physical purge, confirmed timing and native/saved/shared activation are not provided by this contract.

Implementation references: [PostgreSQL lock ordering and advisory locks](https://www.postgresql.org/docs/17/explicit-locking.html), [Supabase function security](https://supabase.com/docs/guides/database/functions), and [Supabase row security](https://supabase.com/docs/guides/database/postgres/row-level-security). The pinned CLI2 and isolated17.11 image are preserved; no platform upgrade is included.

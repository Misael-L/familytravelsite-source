# Unattributed local work archive v1

The qualification utility exports `family.unattributed-work.v1` from `/device-work-recovery.html`. This is an explicit copy under device custody, without a Family account/source assertion. The current v1/v2/v3 owned/legacy account export contracts remain unchanged. This page never imports App/Auth, SDK, Dexie, native sharing or the active database selector. The actual build audit records its dependency graph; its CSP disallows connections. Native desktop/phone Settings contain only a qualification-gated link. No automatic enumeration occurs on entry, consent checkbox change, login or reload.

After explicit consent and Scan, only safe positive numeric `trek-offline-u…` names are offered. One explicitly selected existing version-140 database is opened without a version. Any upgrade transaction is aborted, including an absent-name race. Unknown/older/future schemas, missing/wrong-key stores, auto-increment keys or any key-0 sync metadata refuse without mutation. The utility never creates/upgrades/repairs/stamps/copies/adopts a database. Anonymous and source-owned names are excluded even if numeric IDs match.

One readonly transaction verifies absent ownership and captures queue/import keys and rows consistently. Other stores are excluded. Opaque original fields/status/IDs/revisions/dependencies, key types and supported structured-clone graph values and binary metadata/bytes use the existing lossless codec. Capture time is recorded on transaction completion. Later Blob encoding is cancellable. A concurrent writer can update the database afterward; this remains a point-in-time export, not a lock or freshness guarantee.

The JSON outer envelope is `{format, sha256, payload}`. `sha256` is lowercase SHA-256 of the UTF-8 payload **string**. Payload fields, in order, are `attribution:{kind:'unattributed'}`, `device_origin`, `database:{name,indexeddb_version:140}`, `captured_at`, `automatic_replay:false`, `captured_stores:['mutationQueue','importFiles']`, sorted `excluded_stores`, `counts:{queue,imports}`, and `graph` encoding `{queue:[{key,row}],imports:[{key,row}]}`. Device origin and numeric locator are not a Supabase source, verified identity or server authority. No source_owner field is inferred.

Bounds are 100 candidate database names, 5,000 combined original rows, 16 MiB binary source data, 32 MiB completed JSON archive and the codec's 100,000 graph-node bound. Known credential signatures in text/binary and excluded store names refuse rather than redact. This signature filter is not a general secret detector. Filename is `family-unattributed-work-v1.json`, MIME application/json. A separate ready state and final Download click are required. Cancellation, pagehide, reload and worker controller changes retire the in-memory context; delayed work cannot publish a download. Captures own their cleanup, so an older refusal cannot abort its replacement.

Device consent is separate from an App session. Signing out in another tab neither attributes the data nor verifies ownership; independent device consent persists until explicitly retired. Reload starts without consent. The page states that another person's private unsent data may exist in this browser profile. This is a deliberate device-operator tool, not identity verification or a Family sign-in bypass.

A successful download never acknowledges, marks complete, deletes, replays, uploads or restores originals. It is bounded plaintext, not encryption, an off-device backup, independent database-plus-files restore, or the catalog media backup. The initially supported UI is explicitly English during local qualification; broader localization and hosted/ordinary activation require later review. Ordinary builds emit no recovery HTML/chunk; an unconfigured SPA server may still answer an unknown path with its normal app shell, which is not a recovery utility. Hosting-specific status/fallback behavior is not qualified or changed by these local artifacts.

Acceptance and remaining activation gates are recorded in the canonical `u03d16d-unattributed-recovery-handoff.md`. Existing native Plan layouts remain upstream-exact. No schema, hosted Auth/settings/billing, production/preview deployment, source pin, image transformation, original backup/media or ETL operation is part of this packet.

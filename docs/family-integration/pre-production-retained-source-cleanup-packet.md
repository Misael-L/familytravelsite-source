## Required review and bounded execution

1. Freeze the accepted commit, source inventories, feature matrix, routes, build profiles, recovery/offline/queue contracts and existing tests. Review adopted upstream source alongside Family additions; keep provenance and license/corresponding-source obligations intact.
2. Build a usage inventory from real production and preview entry points, static and dynamic imports, lazy routes, provider variants, feature flags, admin/settings paths, workers/service workers, offline replay, public shares, recovery, CLI scripts and build/test configuration. A successful text search or absence from one bundle is not sufficient proof that an item can be deleted. Keep supported but infrequent compatibility behavior.
3. Classify candidates as active runtime, required compatibility/recovery, development/test tooling, proven unused declaration/file, or unresolved. Record paths, references, applicable profiles, current upstream comparison, evidence and disposition. Unknown usage remains retained; there is no target deletion count or promised percentage.
4. Prefer small removals of proven unreachable private declarations first. Handle duplicate implementations, old versions, stale adapters/assets and whole-module retirement in separate reviewed packets. Never replace a live Family permission/data contract with an upstream backend assumption. Do not touch historical database migrations, source history/tags, original backups/media or ignored ETL as frontend cleanup.
5. For every removal, prove that public exports, reachable routes/actions, native layouts, auth/permissions, session/source retirement, retries/operation identities, recovery and stored image variants retain their accepted behavior. Preserve intentional native UI parity. Any intended behavioral change requires its own explicit scope and acceptance.
6. Run meaningful tests through affected real consumers, typecheck, lint/format/size and the source/native/backend/Git guards under unchanged rules. Confirm no new warnings or silently skipped coverage. Update only the exact source provenance/retirement rows after review; keep historical seals immutable.
7. Rebuild the final ordinary supported-core profile, scan artifacts and recheck affected desktop/phone flows, lazy/admin/offline/recovery paths and provider/image egress. Fresh runtime bytes require fresh acceptance. Finish a clean local source archive and rollback-capable commit before considering preview or production release steps.

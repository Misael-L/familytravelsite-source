# U04-C3c1 — category aggregate database/API contract

This is the database prerequisite of C3c, not activation of native order/Trash/recovery controls. It extends accepted124 with canonical `20261112084121_packing_category_aggregate_commands.sql` on a separate synthetic125 target. Existing category/item UUIDs, ranks, scopes, operation receipts and content remain authoritative. C3b3 application source `0c28618feb9b2e55203041871db7242d16e73839` and saved v3 are unchanged.

## Relational ownership and lifecycle

Reuse `public.packing_categories`, `public.packing_items` and `family_auth.packing_command_receipts`. Add only two private relations: `packing_category_batches` and `packing_category_batch_items`. The batch header primary key `(trip_id,actor_user_id,operation_id)` identifies the original Trash receipt. Its category has a compound Trip/category FK; `deleted_at` and `category_revision` bind the committed deleted category. A partial unique index permits one unresolved batch per Trip/category. Optional `restored_at`, `restored_by_user_id`, `restored_operation_id` are all absent or all present and refer to one typed restore receipt. A restore-receipt lookup index supports that FK.

Each member's key is the original batch key plus `item_id`; its exact `deleted_revision` is stored. Compound FKs bind the batch and actual Trip/item. An item-history index supports reverse validation. FKs use RESTRICT, with receipt FKs deferred for atomic receipt insertion. Header identity and member facts are immutable; a header can resolve only once. No physical purge is introduced.

Full original category facts, raw item rows, recipient/contributor relationships and after facts stay in the existing immutable receipt history. The new relations store identity and lifecycle, not another editable content graph. This is preferable to category flags without a manifest, independent child-trash loops, or duplicating entire item contents in a second archive. It costs two small private tables and deferred validation; it proves exactly which operation deleted which children.

Trash includes exactly the currently live children of the selected category, sorted by UUID, preserving raw historical text, IDs, assignments, bags, quantities and item/category ranks. Items independently deleted earlier are excluded and remain deleted after category recovery. No same-label category, foreign owner lane or unrelated receipt is merged. Recovery restores only the manifest's original rows; current name conflicts, capacities and existing category/person invariants fail atomically. UUID tie breaking preserves deterministic ranks without renumbering unrelated items. Former people/provenance remain historical facts rather than being silently removed/reassigned.

Pending batches require category, member rows and relationships to match their exact immutable Trash facts. Deferred guards prevent an old empty-category restore or individual-item restore from bypassing aggregate recovery. A resolution must prove the complete typed restore receipt and actual restored rows at the resolution transition. Resolved history does not freeze later legitimate edits, moves or another Trash cycle. Unrelated collection edits and Trip Trash/restore do not invalidate a pending manifest; a root lifecycle change does retire an old command's scope.

## Exact public RPCs

All public wrappers are SECURITY INVOKER with empty search_path. Only authenticated receives EXECUTE. Private entry functions are narrowly granted SECURITY DEFINER with empty search_path; helpers, validators and triggers receive no client execute privilege. Both new private tables have forced RLS and no PUBLIC/anon/authenticated/service_role table grants. Existing current Family membership, Person, live session/MFA, Trip lifecycle and direct `trip.packing.manage` rules remain enforced. Propose/deny/read-only access does not authorize aggregate commands. Private category authoring/recovery is owner-only even if a foreign category was shared for reading. Another currently direct-authorized actor can restore a common batch; this does not grant that actor the original author's receipt API.

- `get_family_trip_packing_category_lane_v3(p_trip_id uuid,p_visibility text)` returns exactly `{version:3,kind:'packing-category-lane',scope,collection_revision,lane,owner_person_id,categories}`. `lane` is `common` or the current actor's `personal`; owner is null or that actor's Person UUID. Categories are complete eligible live categories, including retained empties or categories with live items, in `(sort_order,id)` order. Foreign/hidden lanes and dismissed/nonretained empty categories are not members. Each category uses the unchanged full v2 category JSON.
- `get_family_trip_packing_category_aggregate_v3(p_trip_id uuid,p_category_id uuid,p_include_deleted boolean default false)` returns exactly `{version:3,kind:'packing-category-observation',scope,collection_revision,category,items,batch}`. Lifecycle selection is explicit. Live observations contain the complete live member set in UUID order; deleted batch observations contain exactly its deleted manifest members. `items` use existing packing item JSON. `batch` is null or `{actor_user_id,operation_id,item_count}`. A legacy empty dismissal has no batch and keeps its existing v2 restore contract.
- `execute_family_trip_packing_category_aggregate_v3(p_trip_id uuid,p_operation_id uuid,p_scope jsonb,p_action text,p_target_id uuid,p_expected_collection_revision bigint,p_observed jsonb,p_values jsonb)` is the only new writer. `category-reorder` has null target, the complete lane observation and exactly `{ordered_ids:[canonical UUIDs]}`. The IDs must be a unique complete permutation of that lane, never a filtered/visible subset. `category-trash-batch` and `category-restore-batch` identify the category, the exact corresponding observation and empty `{}` values. Restoring is a new operation UUID; the original Trash batch identity remains in the observation. Unchanged retry retains every original command byte/fact.
- `get_family_trip_packing_category_aggregate_receipt_v3(p_trip_id uuid,p_operation_id uuid)` returns exactly `{version:3,kind:'packing-category-aggregate',trip_id,operation_id,scope,status,result_redacted,result}`. `status` is `unknown` or `committed`. Only the original user and original Person context can recover it. Current authorization is required. A known result whose original category/items are no longer readable is redacted; it is not unknown and grants no replay authority. Historical results retain their original scope. Another receipt domain refuses this UUID rather than pretending it is unknown.
- `list_family_trip_packing_category_batches_v3(p_trip_id uuid,p_limit integer default 50,p_before_deleted_at timestamptz default null,p_before_id uuid default null)` returns exactly `{version:3,kind:'packing-category-trash',scope,collection_revision,categories,next_cursor}`. Each row is `{category,batch,item_count}`. This includes legacy empty dismissals (`batch:null,item_count:0`). Common and own-personal deleted categories only; sort descending `(deleted_at,id)`, limit 1–100 and paired finite cursor `{deleted_at,id}` or null. The next page observes current state; this is not a frozen multi-page snapshot.

## Commands and results

A successful writer returns `{version:3,kind:'packing-category-aggregate',trip_id,operation_id,scope,action,target_id,values,collection_revision,changed}` plus `lane,categories` for reorder or `category,items,batch` for Trash/restore. Observe and qualify the exact discriminants, action, original request and scope before publishing. No extra/missing caller fields, rebased observations, selector reconstruction, name lookup or optimistic success inference is permitted. Category values retain raw identity/name semantics; display translations never become identity.

An identical lane permutation inserts only a receipt: `changed:false`, no rank/revision/audit change. A changed permutation assigns zero-based category ranks in the complete lane; only differing category ranks update. Item order is independent. All category commands share the existing `(Trip,actor,operation)` namespace with v1/v2 item/group/category commands. Same-domain identical retry returns the immutable original result; changed intent or cross-domain reuse conflicts. A deliberate second action has a new UUID and fresh observation. Old typed receipt readers reject this new domain; old strict parsers and serialized queues remain unchanged.

Limits: at most 2,000 categories per lane or items per aggregate; 8 MiB observation/returned packet; values at most 256 KiB and scope 4 KiB; combined internal before/after history at most16 MiB. JSON shape and canonical UUIDs are validated before effect. Revisions and collection counters must remain integers within the existing safe protocol maximum 9,007,199,254,740,991. Item/category increments preflight that limit; final collection limits are checked after all affected rows. Any failure rolls back rows, relationships, ranks, manifest, audits, counters and receipt together.

Error classes are intentional: `22023` malformed contract, `PT409` stale original/changed context/operation conflict, `42501` denied current authority, `54000` size/count/counter limit, existing FK/check errors for data-integrity violations, and `0A000` unsupported legacy-empty/batch domain or unsafe downgrade. Never interpret an unknown or failed acknowledgment as permission to resubmit with a new identity.

## Transactions, review and release boundary

Writer lock order: shared Trip-recovery advisory lock, Trip FOR NO KEY UPDATE, packing state FOR UPDATE, category/header and UUID-ordered item rows, recipient/contributor rows, category assignments. Recheck current membership, session expiry/MFA and direct permission after waits and at the end; compare original scope/Person again before commit. Complete observations are compared after locks. The operation is one PostgreSQL transaction; deferred relational guards are backstops, not a substitute for its validated entry point.

Only two existing function bodies are extended: typed-domain dispatch in `packing_receipt_entry` and result visibility dispatch in `packing_result_visible`. Old owners/grants/configuration and unrelated functions remain exact. The migration pins the124 ledger and those reviewed function bodies. Its separate125 guard pins the canonical source/ledger,124-file prefix,94 packing functions and schema/security contract. Earlier guards are not repointed or relaxed.

The pre-authoring rollback is only for a marked synthetic rehearsal and refuses any aggregate receipt or batch/member history. After authoring, use a proven rehearsal restore rather than deleting recovery facts. No hosted rollback command is provided. See the acceptance handoff for actual tests; C3c2 must still implement strict SDK/transport/queue/native integration and actual desktop/phone acceptance before activation. The previous native presentation, saved v3, source pin and stored image variants remain intact.

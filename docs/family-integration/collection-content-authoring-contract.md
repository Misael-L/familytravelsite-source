# U04-F5c4 — observed Collection item authoring contract

Local schema140 prerequisite. No native control activation, root-authoring cutover, transfer, hosted change, push, source repin or byte operation. Preserve C1 recovery, C2 typed storage/history and C3 explicit reads.

## Actions and original operation

Five invoker APIs call one checked private definer dispatcher, with empty search_path and authenticated-only execution:

- `get_family_collection_authoring_context_v1(p_collection_id uuid,p_target jsonb DEFAULT '{}')`: explicit active-item-edit authority. Target exactly `{}`, `{item_id:uuid}` or `{source:{kind,id}}`. Return version/scope and observation `{version:1,collection_revision,content_revision,lifecycle_revision,item_revision,item_digest,source_digest}`. Item/source fields are null when irrelevant. Item observations reuse C3's conservative whole projection; source/derived-media change requires explicit re-observation, never silent field omission. Source context includes the canonical source facts; all-state exact-source duplicate status stays explicit. Empty target includes complete ordered active-item IDs/revisions up to100; beyond that it reports order_complete=false and ordered_items=null. Normal creation remains supported in larger Collections, while full reorder refuses54000 above100. Context is bounded256KiB.
- `prepare_family_collection_content_v1(p_collection_id uuid,p_operation_id uuid,p_action text,p_body jsonb,p_observation jsonb)`: lock the Collection, pin/recheck authority and exact observations, freeze server-derived canonical intent and register its immutable original. Exact request hash and actor/session/list/op identify retries; identical lost-prepare replies return the same original, not new source values or target ID. Input/original <=256KiB. Maximum200 pending operations per actor; explicit54000 on excess. No automatic retention purge.
- `execute_family_collection_content_v1(p_collection_id uuid,p_operation_id uuid,p_original jsonb)`: exact registered original, original execution session, current permission, lifecycle/revision/source/body observations, checked locks and atomic final content/history/outcome. An existing owned outcome is acknowledged without reapplying or returning stale content.
- `get_family_collection_content_operation_v1(p_collection_id uuid,p_operation_id uuid)`: current authorized actor can discover prepared/committed/cancelled/unknown, including a fresh session. Committed/cancelled receipts are minimal; prepared discovery returns the owned immutable original for recovery/cancellation. No historical receipt overwrites newer content.
- `cancel_family_collection_content_v1(p_collection_id uuid,p_operation_id uuid,p_original jsonb)`: exact owned original and current recovery authority; may cancel from a fresh session. Serializes on the same actor/op advisory lock as execution; returns an already committed outcome truthfully or retains cancellation so that original can never execute later.

Original is `{version:1,scope,action,target_item_id,body,observed}`; target ID for creation is server-generated once. Context/observations and original scope are canonical DB facts, including nullable person, exact session and Collection lifecycle. The caller must retain this original unchanged; no ambient identity/source rebind. Private immutable command and outcome tables retain intent/results. Private transaction capabilities cannot be populated by application roles. Both C1 and C4 reserve the same actor/op namespace and advisory lock: a lifecycle ID cannot be reused for content or vice versa.

## Exact body shapes

- `create_reference`: `{source:{kind,id},notes,status}`. All eight typed catalog kinds are representable. Name is inherited (NULL), not client-provided catalog data; notes are personal. Source digest is required in the observation.
- `create_snapshot`: same input, only place/food/hotel/experience. Derive name/description/own coordinates/address/website/phone/media ID from the observed canonical source. Snapshot values are normalized/validated before the original is returned. Unrepresentable legacy source text/website/media refuses0A000 rather than losing it or accepting arbitrary fields with a source ID. No price/currency or provenance invention.
- `create_manual`: `{content,notes,status}`. Content has exactly name,description,latitude,longitude,address,website,phone,family_place_category_id,cover_media_id (including explicit NULLs). No source FK.
- `materialize`: `{item_id}`. Existing location reference only; freeze its canonical content, preserve saved name if present and personal notes. Already materialized is an observed unchanged outcome, never implicit re-inheritance. Nonlocation kinds refuse0A000.
- `edit`: `{item_id,changes}`. Only name/notes plus description,coordinates,address,website,phone,Family category and cover ID on an existing snapshot. Reference name/notes edits are allowed; other fields require explicit materialization. Omission preserves; NULL/empty is an intentional clear. No identity/source/list reassociation, status hidden in edit, URLs for images, tags/labels/links/provider IDs, price or currency.
- `status`: `{item_id,status}`; exact idea/want/visited.
- `reorder`: `{ordered_ids:[uuid...]}`;0..100 unique IDs, exactly every active item in this Collection. No partial reorder, duplicates, foreign/trashed items or omitted typed references. Observe aggregate revision; row locks sorted by UUID. A no-op retains revisions but still requires current authority and creates a truthful outcome.

All new names are trimmed1..500; notes/description <=20,000 Unicode characters with exact internal whitespace and NULL/empty semantics. Legacy untouched reference text remains preserved. Text fields have C2 limits, coordinates are a nullable pair, finite/ranged and already rounded to8 decimals; execution never rounds. UUIDs and numeric values must be canonical before observation. A standalone, currently unwired backend input normalizer uses the platform URL parser for HTTP(S), rejects credentials/control/backslash and canonicalizes precision/URLs before API observation. DB storage/prepare also validates its conservative canonical grammar. Source URLs that cannot be represented without an unqualified rewrite refuse explicitly; the DB does not pretend to implement WHATWG parsing.

## Authority, lifetime and concurrency

Root-first content locks and authority rechecks after waits; typed source rows FOR SHARE before re-observing, scoped categories and sorted media locks. New pending-media holds participate in existing cleanup-reference and immutable media scope/path/hash fences. They retain intended bytes until execution/cancellation resolves; late failure leaves the original prepared and hold intact. Commit replaces pending holds atomically with live/version holds. Cancellation releases only its own pending holds. Test both cleanup lock winners using synthetic metadata only.

Current private/Family membership, session expiration/revocation, MFA and Direct source rules stay enforced. Creation still requires a recorded same-Family creator; global read/recovery authority does not invent one. Fresh-session discovery/cancellation is distinct from original-session execution. Archived/trashed parents refuse new mutations; authorized historical outcome discovery is separate. A failed history/outcome write rolls back item/child/order/revisions/context and outcome together. Original registry/outcomes are immutable, private and never raw readable or writable by app roles; no permanent media FK is stranded after cancelled holds release.

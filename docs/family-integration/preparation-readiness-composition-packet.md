# U03-D16k — truthful preparation readiness composition

Prerequisite: D16j's sealed local qualification. This packet designs and proves the component result/ownership contract before deciding how native whole-Trip preparation can be exposed. It does not imply every file is durable or every native download control can be enabled.

## Purpose

The accepted metadata, public-image and private-file components have different lifetimes. A complete published metadata generation is time-limited private information; public variants can be shared and evicted independently; D16j private bytes are limited, unversioned and RAM-only. Native TREK's whole-Trip `done/trips` result cannot currently express those distinctions. Combining successful component receipts must not manufacture a blanket offline-ready promise.

## First bounded implementation

Inspect the actual `prepareForOffline`, `PrepareProgress`, `SyncOutcome`, native desktop/phone callers, tile/place cache assumptions and current Family capability gates. Specify one source/account/Trip/generation-owned, token-free component status model. Distinguish metadata admission, public images, private warm-memory files, map/search coverage, unsupported/deferred items, partial failure, cancellation, expiry and later eviction. Include a durable-after-restart versus current-document-only distinction. Record any unresolved product decision before enabling a misleading control.

Compose existing real admission adapters and acquisitions; do not duplicate authorization, signers, file parsers, public capture, database ownership or saved-read verification. Recheck actual residency when reporting readiness; an earlier receipt or completed callback is not a current lease. Preserve per-component budgets and explicit user intent. No automatic all-file/all-trip/background download, wider private metadata lifetime or encrypted persistence in this packet.

Scope permitted code to a new Family preparation/status adapter, its focused contract tests and existing native API adapter boundaries only where the full caller/return contract is satisfied. Keep native markup/styles/layouts unchanged. If native whole-Trip success cannot be represented truthfully, keep `planner-scope` refusal and document the exact outstanding contract rather than reporting a trip prepared.

## Required cases

- Same original generation with empty, complete, partially missing and failed public/private components.
- Untouched original queue/import/File data and layer/account/source/Trip/database ownership fences, including ABA and late callbacks.
- Original complete generation replacement/expiry and reconnect; cancellation while each component is pending.
- Private four-entry/64 MiB reservation limits and per-file 50 MiB ceiling, explicit retries/refresh and failed known-access checks.
- Public eviction and private document restart cannot retain an earlier ready claim. Original receipt data cannot grant access.
- Both native desktop/phone callers receive honest outcome/progress and remain gated wherever coverage is unsupported. Ordinary/source-alias and image-variant/zero-transform behavior remain covered.

Run configured typecheck, focused tests, unchanged quality gates and a final frozen-input full suite, preserving prior assertion/status multiplicities. Use actual built native consumers and marked local fixtures for any newly enabled behavior. Reverify source/schema/native/layout/carryover and original domain/audit/Storage preservation; seal evidence and a local scoped commit.

## Boundaries

No push, main merge, production/preview deployment, hosted database/settings/billing, dependency/version change, transformation/backfill, original media/backup or ignored ETL change. Persistent private caching, longer offline authority, source-pin/whole-version acceptance, packing authoring, independent restore/incremental backup work and release retain separate gates. Do not start a new broad feature migration to avoid an unresolved readiness decision.

## Outcome — locally qualified

The bounded read-only status adapter is accepted. It does not enable native whole-Trip preparation, persist readiness or grant private access. See the D16k measured handoff/progress and status contract. Next is D16l whole-version acceptance consolidation, keeping optional download coverage gated.

## Exact identity and input contract

Use a typed descriptor `{ source, mediaAssetId, recipe: 'v1', role: 'thumb' | 'hero', url }` from an already validated caller, not inferred from a native numeric ID or a cached URL. `source` is the trusted active Supabase base URL supplied independently by the caller/config, not derived from `url`. Validate media asset identity and role; the same asset's thumb and hero remain distinct entries.

Accept only the exact source origin and exact `/storage/v1/object/public/catalog/variants/v1/` prefix with a nonempty `.webp` object name. Local `http` is limited to the two explicit fixture sources; other test-only/production policies must not be enabled by this packet. Reject userinfo, query, fragment, alternate origin/port, redirect, encoded separators/traversal, backslashes, empty/dot segments and paths that normalize into the allowed prefix from an invalid raw path. Reject `/render/image/`, `/object/sign/`, originals, arbitrary bucket names, avatars, user covers, provider URLs and private files **before any fetch/cache write**. Do not reuse the legacy `isReadyCatalogVariantUrl` substring predicate as this admission policy.

Cache identity includes the exact trusted source plus canonical object path; typed receipts additionally retain asset/recipe/role. Canonical and localhost sources must not share entries. Public bytes may be shared across accounts for the same exact public source/path because they are publicly accessible; that does not confer membership or a private Trip association. Do not store Auth, Family, Person, Trip, file routes, tokens or signing URLs in this public cache. A private preparation receipt remains scoped to its own actor/Trip/generation in a later packet.

## API and bounded storage

Expose a small factory with injected fetch, CacheStorage, time and current-operation/AbortSignal dependencies. Suggested operations: `capture(descriptor, context)`, `read(descriptor, context)`, `remove(descriptor)` and `clearSource()`. Return a discriminated result: a checked byte receipt/Blob, a cache miss, or an explicit refusal/failure/cancellation. Never return a fabricated ready receipt after an exception. A receipt identifies the format version, trusted source/path, asset/recipe/role, actual MIME/byte length, locally computed SHA-256, capture time and expiry. The local digest detects stored-byte corruption; it does not prove server authenticity without an independent expected digest.

Use a dedicated versioned CacheStorage namespace per exact source, unrelated to `api-data`, `user-uploads`, native `blobCache`, complete heads, command/import stores and static precache. A response body and its validated public metadata should commit as one cache entry. Await persistence and reread/verify before returning a stored receipt. Do not mutate an existing complete envelope or make its `bytesAvailable=false` become true implicitly.

Initial explicit bounds: **4 MiB per image, 64 MiB and 128 entries per source, seven days of public-byte retention**. These are modest device-cache limits, not a backup or private metadata retention policy. Oversized images are unavailable for this cache; the source remains untouched. No upfront scan/download of the full catalog. Reads never extend expiry or the complete Trip's fifteen-minute deadline. Expired/corrupt entries become misses. Read-only cached hits must work without network. Missing/stale/quota-denied bytes do not imply a whole Trip is ready.

Enforce bounds on the streamed body (including absent/false Content-Length) before accumulating the limit; reject empty, truncated, opaque/non-OK/redirected and non-WebP responses. Fetch only the accepted public URL, `credentials:'omit'`, `redirect:'error'`, with the caller signal and no Auth headers. Use actual byte count, WebP signature and browser decode verification; header-only validation is insufficient. Check the operation/source lifetime before and after each asynchronous fetch/body/hash/cache/receipt boundary; an A→B→A return does not revive an old operation. Do not fall back to transformations or canonical originals.

Serialize writers per source within an instance and use a browser lock for cross-instance/tab mutations of that source cache. If a safe lock is unavailable, reads may proceed but writes must explicitly refuse. This keeps deterministic insertion-order eviction and exact source bounds honest. Recheck lifetime inside the lock. Evict only that cache's oldest successful public entries to make room; never clear unrelated stores. Cancelled/stale operations must not publish a ready receipt. If cancellation happens during an unavoidable Cache API write, settle it under the lock and clean up only that exact operation's entry; do not delete a newer replacement. Preserve a prior valid entry when refresh fails. Quota failures may leave fewer public entries after bounded eviction, but never delete private originals or report the failed new item ready.

Use same-source request keys without `ignoreSearch`/`ignoreVary` shortcuts. Independently verify stored metadata and actual body/digest on reads, including recipe/role/asset binding and bounds. An unexpected receipt/schema or a digest mismatch is a miss/refusal, not a reason to reinterpret an unknown format or clear other namespaces.

## Required regression cases

1. Valid thumb and hero capture, awaited persistence, independent reopen/read, exact Blob bytes/digest/MIME and distinct roles; duplicates are idempotent and a valid cached hit performs no fetch. Changed object path is a new identity, even with the same asset ID. A different asset/role cannot relabel an existing receipt.
2. Every forbidden URL form above rejects before network/storage. Equal asset/native IDs across canonical/localhost sources cannot share bytes or readiness. No private identity is serialized into public entries. Unknown cache format remains untouched except an explicitly documented miss.
3. HTTP failure, redirect, opaque response, HTML/error body, incorrect type/signature, truncated WebP, missing/misleading Content-Length, empty body and streaming overflow fail without new ready entries. Valid browser decoding is tested with a real synthetic WebP, not an always-successful decoder mock.
4. Signal/source retirement during fetch, stream, hashing, put and reread; A→B→A, overlapping writers, lock refusal, delayed cleanup versus a newer replacement. A stale success cannot acknowledge a current run. Storage/crypto exceptions reject explicitly without unhandled promises or fabricated receipts.
5. Clock rollback, expiry boundary, malformed/extra receipt fields, corrupted bytes/digest, eviction/count/byte limits, no-lock platform, quota failure, repeat retry and failed refresh of an existing good object. Do not test implementation details instead of these behaviors.
6. Seed unmarked/current-owned opaque commands and compound-key binary imports before browser cache tests; exact store keys/metadata/bytes remain unchanged afterward. Existing complete envelope/head and private file stores remain exact. No signing or domain command occurs.

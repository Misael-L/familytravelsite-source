# U04-F5b1 — native Collection transfer safety

14 November 2026. Parent82fd5dcac, existing `codex/trek-v5.1.4-family-reconcile` branch. This packet repairs demonstrated unsafe/unconnected write paths; it does **not** complete normalized Collection conversion or global-page parity.

## Behavior

Native Family POSTs to `/addons/collections/places`, `/places/from-trip`, `/places/from-trip-many` and `/copy-to-trip` now return422 `collection_transfer_unavailable`. They authenticate and retain the existing request-context fences, then refuse before parsing domain IDs, loading items or calling a legacy writer. A privileged role, a coincidentally matching city UUID or a retry key cannot enable a disconnected feature. This deliberately withdraws the older from-Trip/copy implementation that treated a saved location as a shared geography record. Previously unsupported native save/bulk routes now receive the same meaningful error instead of an unrelated identity/backend error.

The existing desktop/phone save hook displays the error, retains the target and its notes and leaves its success/version state untouched. The copy hook reports the error and leaves the picker open. Native layouts are unchanged. Existing list detail, item identity, status and removal paths are not routed through this transfer gate. Their preservation is tested at the handler boundary; this packet does not newly qualify their database/recovery semantics.

The old service-compatibility tests that expected successful geography copying are replaced by explicit refusal assertions. The app-config test now reflects the catalog autocomplete/details/enrichment flags already enabled by F5; provider photos, service identity, community contribution and routing remain unavailable. No runtime app-config flag changes occur here.

## Why acceptance remains blocked

Matching object bodies and migration counts did not establish the qualified permission contract. The reference intentionally inherits source platform/bootstrap ACLs. The final independent comparison with F2's qualified128 snapshot found **seven extra effective grant fields**: authenticated table-wide INSERT on `trips`, INSERT/UPDATE on `schedule_items`, INSERT/UPDATE/DELETE on `media_assets`, and anonymous EXECUTE on `catalog_media_urls(text,uuid[],integer)`. These broader source grants survive the forty migrations. The visit bridge grants intended columns without first revoking pre-existing table-level INSERT/UPDATE; the old media helper revokes PUBLIC without removing a direct anon grant.

A read-only metadata comparison with the previous strictly guarded qualified128 target also finds183 raw relation ACL differences,198 routine ACL differences and21 matched default-ACL differences; three default entries exist only on each side. **These raw counts are not vulnerability counts**: grantor/role/platform differences require effective-permission classification. Column ACLs are identical. `TRUNCATE` remains granted to non-administrative roles on affected tables even in the earlier qualified fixture; copying that fixture wholesale would preserve a separate bypass risk. No permission was changed to hide these findings. Source ledger and data preservation remain valid; release acceptance is explicitly false.

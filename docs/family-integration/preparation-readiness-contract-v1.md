# U03-D16k — preparation status contract

This is an explicit local read-only component observer. It is not installed as a default product consumer or a replacement native screen. The native whole-Trip preparation control still returns `skipped / planner-scope`.

## Original admission

`openPreparationReadiness(trip, repo)` uses the same `admitCompletePreparation` as the accepted image/private components: actual SDK/Family/native identity, source/database, visible published Trip, real RLS-protected Trip header, original complete owner/head/body generation and original command/import blockers. `preparationComponentRead.ts` extracts the existing image component's lifecycle unchanged so both use its original owner/deadline/queue/import checks. Its accepted image refusal class and existing regression identities remain.

The observer is online-only. Offline transition, actor/session/Trip/layer/source retirement, stored generation replacement, original-work/import changes, original expiry or disposal retire it. Reconnect cannot revive the same handle. A separately qualified saved-file view remains independent and can display D16j's prepared memory after this observer closes. Status inspection never changes Family permissions or grants additional offline authority.

## Explicit inspection

`inspect({ signal? })` performs current checks before, during and after the observation. It independently rereads the actual public cache and private RAM pool each time; it accepts no prior component receipt as proof. It does not call capture, preparation, acquisition, signing, repository file-open, native cache adoption, queue replay or domain writes. Constructor/opening performs no media capture.

One run inspects at most 32 eligible public variant descriptors and 32 eligible file IDs. Extra items are **deferred**, not assumed ready. Shared public selection/matching helpers preserve the accepted asset/role/recipe/source rules; repeated covers are deduplicated, missing metadata remains unavailable, and originals/transformations/unrelated gallery assets are not substituted. Cache reads use the accepted strict digest/MIME/WebP/decode implementation; no public cache entry is created or repaired merely for status.

Private selection uses the accepted file parser and existing 50 MiB per-file limit. Unsupported metadata is separate from an eligible but unprepared file. The original four-entry/64 MiB reservation pool remains unchanged. Its new optional read-only `inspect(read, files, signal)` verifies the independently bound original read before returning ready/pending/missing states. It exposes no Blob, digest, signed URL, browser URL or file content, and performs no acquisition or allocation of private bytes. Duplicate/more-than-32 probes refuse. Pool disposal and caller abort settle a stalled read verification even with no slot. A cancelled acquisition is missing, not ready/pending. Old providers without the optional inspection method are never queried through a legacy blob fallback.

The composer validates the response set and statuses and refuses a pool replacement during inspection. A private observer error produces failed counts if the common original read remains valid; a common admission/owner verification failure aborts the whole observation rather than publishing partial success. Concurrent calls return busy rather than merging results. Cancellation/expiry and original owner checks fence late promises; separate observers do not dispose each other's components or shared bytes.

## Result

The transient `family.preparation-readiness.v1` result includes original source/scope/ownership, complete generation/digest, original expiry and observation time. It is token-free private metadata and is not persisted. It contains no file paths, names, bytes, signed URLs or Blob URLs.

- Metadata reports independently checked availability in the existing IndexedDB generation and its original expiry. No TTL/media flag is extended.
- Public images report `empty`, `complete` or `partial` plus ready/missing/failed/eligible/inspected/deferred/unavailable/no-cover counts and CacheStorage as their storage class.
- Private files report the same component states with ready/pending/missing/failed/total/inspected/deferred/unsupported counts. Storage class is **document memory**. With any file in scope, restart availability is **unavailable**, even when every inspected eligible file is ready.
- Map/search coverage is **unsupported** (`family-map-search-unqualified`). This packet does not equate a cached map shell, coordinates or static worker assets with downloaded map/search coverage.
- `wholeTripReady` is always false. `nativeOutcome` is typechecked against the real `SyncOutcome` and remains exactly `skipped / planner-scope`.

Counts are fresh per-item scan observations, not an atomic transaction across IndexedDB/CacheStorage/RAM or a guarantee against subsequent eviction. They are not byte leases, authorization grants, immutable server content versions or input to a whole-Trip success gate. Consumers must inspect again for a later observation. A prior successful public receipt, private receipt or observation cannot renew private authority or prove residency after eviction/restart.

## Native contract decision

Native `PrepareProgress` has trips/files/tiles/done phases and `SyncOutcome.done` has only a trip count. Desktop OfflineTab and phone MSettingsOffline share `useOfflineSettings`, which turns done/trips into a stored banner. Those contracts cannot present this component-only/current-document result truthfully. The guarded native API, shared hook, notice mapping and native markup/styles/layouts remain unchanged. No synthetic done event, trip count, progress, new UI or false stored banner is supplied.

Persistent private files, longer offline metadata retention and map/search preparation are optional unimplemented capabilities, not reasons to silently extend this packet. A supported metadata-only release can keep them gated; remaining whole-version/source/capability/worker acceptance must be reviewed separately before source-pin adoption, packing authoring or a preview/main release. Independent restore/incremental backups stay separate.

## Acceptance and boundaries

Actual built local desktop/phone checks use real App/SDK/password/TOTP/worker, native file consumers and private Storage/RLS. Public image HTTP bodies are controlled tiny WebP fixtures. The older unsupported/mismatched text file is preserved and truthfully counted unsupported; a separate eligible WebP proves positive RAM preparation. No original record/file is repaired. New query/Storage preservation checks prove both status fixture graphs/audits and all four original Storage object byte hashes unchanged, alongside the older source/schema/domain preservation checks.

The handoff/evidence contain the final full/focused/type/gate/lint/process and source/artifact hash receipts. Ordinary/qualified/source-alias product graphs are compared byte for byte to the accepted parent; inherited product browser results are distinguished from fresh qualified-entry checks. Physical iOS/Safari and hosted policies are not claimed. No push/main merge/deploy, production/preview/hosted schema/settings/billing/dependency update, transformation/backfill, original backup/media or ignored ETL operation.

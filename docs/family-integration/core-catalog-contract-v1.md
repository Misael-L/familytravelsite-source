# F5 native Family catalog connector contract

Starting source:98764f54d; native contract: TREK5.1.4, upstream2bcfc1b. No protected layout or schema change. The backend already supports catalog source selectors in the observed native creation transaction; the frontend currently emits manual-only creation and has no POI route.

Read-only native endpoints: `GET /maps/pois` requires category and finite viewport bounds; `POST /maps/search`, `POST /maps/autocomplete` return bounded genuine matches with coordinates; `GET /maps/details/:id` resolves a typed catalog key. Selected detail/enrichment reads use only current ready-v1 objects or placeholders. No provider call, original-image fallback or transformation. Unknown provider IDs are unavailable, never silently interpreted as a city or manual venue.

Catalog keys retain `catalog:<kind>:<uuid>` through native `osm_id`, including the distinct place/geography kind. Restaurant/cafe/bar/hotel/experience pins query their own tables and coordinates. Related city identity is context only. Map bounds, archive status, type-code membership, result caps and deterministic ordering are enforced. Explicit unavailable categories/errors differ from a genuine empty result. Query/category cancellation and source/actor/Trip retirement reject late answers before consumer publication.

Creation accepts a typed selection only after a current catalog read. It preserves the exact source kind/id in `create_family_native_plan_v1`, retaining transaction permissions, Direct/Propose/Deny, original operation IDs, lost-reply behavior and fresh deliberate repeats. The catalog observation is frozen per open form so retries do not mutate an unresolved original. Notes belong to the saved Trip location; catalog description stays inherited unless intentionally overridden. The existing pool uniqueness is preserved; another visit uses the existing normalized saved location rather than duplicating a venue. A duplicate catalog save must refuse with clear guidance rather than silently dropping edits.

Permitted implementation: new Family backend discovery reader and frontend native-map adapter, narrow application-handler dispatch, catalog-aware creation mapping and native saved-location source projection, related tests and docs. Native layout/style, route roots, dependency versions, adoption pins, canonical SQL/migrations and prior sealed evidence remain unchanged. No hosted SQL/settings/billing, migration, remote push, public publication, preview/production deployment, transformation, backup/media or ETL work.

Acceptance: real backend query construction/projection and handler-to-native hook/form tests; repeated visit and retry/identity tests; abort/source/actor/Trip/error/empty/invalid-type cases; media ready-object/placeholder tests; typecheck/lint/build; isolated upgraded-target and desktop/phone proof before claiming the whole F5 discovery-to-save journey complete. Partial mocked proof alone is not release acceptance. Existing global-page placeholders remain explicitly inventoried; this is not full TREK feature parity.

Execution-discovered scope: only the Family branch of `permissionsStore.ts` reads the live permission controller for retained native callbacks; its subscription remains for UI refresh. The native form adapter accepts only absent `duration_minutes`, never a real disconnected duration. These changes are covered by native opener/payload regressions. Native photo credit is explicit and no museum taxonomy is fabricated.

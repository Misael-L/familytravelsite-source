## Implemented and preserved

The existing `lists` and `list_items` gain server-owned revisions and recoverable tombstones. Archive remains independent. Root Restore preserves Archive and independently trashed children. Private immutable root/item versions retain old committed content and the final state of a changed transaction. Unchanged legacy rows acquire no invented history. Personal notes, all eight typed catalog identities, status, ordering and existing IDs remain intact. All eight destructive catalog cascades now roll back at the recovery guard; their FK definitions are unchanged until the content packet.

The nine contracted public APIs are installed locally as thin invoker wrappers over one checked private entry: metadata-only root/item context; bounded root/item Trash pages; root/item observed Trash/Restore; bounded versions; original outcome lookup; original cancellation. The item lifecycle argument `p_expected_collection_revision` observes aggregate **content_revision**, while context and acknowledgement `collection_revision` identify the root metadata revision. Neither is a fabricated native Place response.

Commands bind the current actor, person, Family, session and lifecycle, preserve the original operation ID/body, return historical acknowledgements on matching retries and refuse stale or changed originals. Unknown outcomes remain unknown; cancellation serializes with execution and cannot undo a committed action. A late receipt or deferred-history failure aborts the entire mutation. New sessions may inspect an authorized owned outcome, but cannot execute an old session scope.

The three existing public list predicates are hardened **in place**: original OIDs, owners and ACLs remain. List creation now also checks current session/Family/MFA authority. The old physical-remove RPC explicitly refuses. Other legacy add/status/reorder/metadata writers are only compatibility paths guarded by current authority/lifecycle/history; they are not a newly qualified observed authoring cohort and must not compete with a future content writer when enabled.

One implementation refinement changes the earlier lock-order wording: perform a preflight authority check, acquire the root, then pin and recheck current Auth session, profile, membership, person and MFA rows before the child/write. Holding membership locks while waiting for a root would prevent a revocation from committing during that wait. Real concurrent tests instead prove committed membership/role/person/session/global-admin/MFA revocations are seen and refused. Original-operation locks still precede target locks. No caller-set GUC authorizes lifecycle changes: a private transaction-scoped permit exists only inside the checked command.

Root-cover versions retain media IDs through concrete private junctions. The existing reference predicate retains every previous source and adds Collection version holds. A shared path lock coordinates new holds with the existing cleanup revalidation entry; an already armed object refuses a new hold. Media identity is rechecked after row-lock waits. Original bucket/path/hash become immutable while retained. Root edits acquire old/new media holds in deterministic ID order. No byte cleanup, download, upload, inventory or transformation was performed; race tests used new synthetic metadata only.

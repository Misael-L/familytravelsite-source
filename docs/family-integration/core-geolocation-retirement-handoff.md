## Result and deliberately changed behavior

The old hook allowed a stopped watch's callbacks to mutate current state, clear its replacement and undo a later stop. Success, error and orientation callbacks now compare the existing start-run generation before reading a payload or changing state. The queued compass state updater checks that generation again when React applies it. stopWatch increments the generation before calling clearWatch, so even callbacks delivered synchronously during cleanup are retired.

A registration's returned watch ID is retained only if the same run is still current. A synchronous permission denial can retire that run before watchPosition returns; the newly returned ID is then cleared exactly once instead of being leaked. A small clear helper preserves the existing exception tolerance. startWatch internally returns its successful generation or false; cycleMode verifies the generation after its original await. A pending old cycle therefore cannot reopen a stopped/replaced/unmounted run. No new asynchronous boundary or external API is introduced.

One runtime file and one new durable test file change. Public hook/one-shot types and exports, imports, state/ref/effect call order, callback dependencies, watch options, permission gesture/await, normal current-watch success/error/recovery/denial, heading conversion/smoothing, functional mode updates and native layouts remain. The two copied Q92 projections and earlier application/router work are unchanged. Other lifetime behavior is outside this repair; no universal cancellation guarantee or real-device acceptance is claimed.

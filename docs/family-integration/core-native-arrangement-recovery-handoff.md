## What changed

Native Move, reorder, Trash and confirmed Clear now enter `PlannerCohortAssignments` through immutable pre-dispatch IndexedDB retention, the existing owned Web Lock and a dedicated arrangement session. All five backend actions are covered, including Restore through native Trash Undo. Invoked Trash/reorder Undo sets the same pending guard and persists its exact captured plan before any arrangement outcome or write RPC, even though native history consumes its own UI entry. No native history, layout, CSS or presentation file changed.

`arrangementIntentQueue.ts` uses the existing account/source-owned queue and schema/build metadata. It preserves the original API source, actor/Family/person/Trip/layer, operation UUID, target/revisions and complete observed days/order/plan. Storage failure or a missing required Web Lock sends nothing. An uncertain or refused original remains retained; a different gesture cannot replace it. Malformed/changed metadata, extra Trip work, armed creation-terminal state or a retired owner cannot be acknowledged by an old callback. Generic queue flushing cannot replay it as an unchecked write.

`arrangementReceiptTransport.ts` calls only `get_family_native_arrangement_receipt_v1` for Check. It requires exact original scope/plan/Trip/operation echoes, the bounded typed envelope and lowercase digest; it validates historical affected/removed identities, revisions, anchor, layer and no-op/private operation distinctions. Unknown never writes or clears work. Retry can send only the original packet/UUID, then requires a matching committed proof and the same digest/result before deleting only the still-observed original. Current session/source/account/Family/person/Trip/layer and visibility fences surround asynchronous boundaries. Receipts are not borrowed from creation, editors or the lower arrangement domain; creation cancellation is not offered for arrangements.

`plannerArrangementRecovery.ts` connects cold discovery to the existing recovery surface without publishing a planner snapshot. Committed proof acknowledges only its matching original; the normal recovery surface then reloads canonical state. Warm success also refreshes canonical state. A historical result is never reapplied as current order. Undo is prepared only while the refreshed visible order and occurrence revisions still match the historical acknowledgement; later revisions cannot become a reconstructed old Undo. Submitted/removed private historical work is acknowledged without recreating it and does not masquerade as a new active draft.

The native dispatcher now checks the current owner/layer and retained queue compatibility before calling the existing writer. Two old generic-queue replay expectations now explicitly require retaining work on a changed layer or outside explicit recovery. The old lost-successful-reply test now requires read-only confirmation, one operation/receipt and no duplicate write. Its identity/revision protections remain. No tests were skipped or removed.

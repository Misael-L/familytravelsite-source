## Repaired behavior

Native new-place creation and the shared Add-to-day producer now persist the original complete command in the existing source/account-owned IndexedDB before dispatch. Storage failure sends no command. The row has one original operation UUID, source, account/Family/person, Trip, layer, complete form, schema/build version and creation time. There is no optimistic success or replacement native place cache.

The initial send and recovery use the same stored body. Acknowledgement requires a validated saved result plus `get_family_native_plan_receipt_v1` confirming the exact operation, Trip, scope and form. Removal is transactional and compares the entire observed row under the current owner. Unexpected replies, changing metadata, permission refusal or interrupted sessions retain the original.

Cold reload exposes the existing retained-work recovery surface with planner labels. Check reads the receipt and never executes an unknown command. Explicit retry checks first, then sends that original only when unknown. A committed receipt clears the matching original without another command. Current source/account/Family/person/layer, visibility, native identity registry, owner session and exclusive queue lock are checked throughout. Logout and a fresh authorized same-user sign-in can recover the original with current database authority.

The general queue now unconditionally holds the creation protocol, including legacy resource-bearing rows. Such rows are not silently converted or replayed as qualified originals. The dedicated recovery handler accepts only the finite original protocol. Existing task/base-packing behavior and all12 native TREK presentation pins remain unchanged. The selected synthetic planner profile adds only the exact receipt reader to its read set; ordinary/primary/task-only and advanced-feature restrictions remain intact.

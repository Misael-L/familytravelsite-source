# P04au real application read rehearsal

Run from the integration repository with Node 24 and `P04AU_OUTPUT` set to a writable local evidence directory:

    node client/tests/browser/planner-application/run.mjs

The actual UUID route boundary, explicit cohort and native desktop/phone planners are used. The actual application, list, budget and file handlers consume named synthetic SDK SELECT rows through the preserved backend mappers. Optional contributions use their real empty-provider handlers. Legacy `repo.core` throws. The fixture preserves the eight-location/four-day/ten-visit scenario from the prior native rehearsal, including repeated visits. Each editor saves one canonical observed location, reloads it and switches to My Draft.

The two explicit application stubs are weather and notification count. Authentication/session, planner/governance RPCs, Trip header/category reader responses, media raster bytes and normal phone provider routes are local synthetic fixtures. Every unknown SDK table/RPC or unhandled external request fails. Queries and RPCs fail if they inherit an IndexedDB transaction. No live SQL, RLS, Auth, Storage, Realtime or production provider claim is made. Do not deploy this fixture or the localhost qualification build.

Evidence includes direct Axios results for nonempty lists/costs/files/travelers, native startup models, screenshots, query/RPC/request logs, editor observations and final queue state. Tours and route-planning integrations remain off. No native page markup/styles are changed.

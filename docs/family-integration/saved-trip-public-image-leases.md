# Saved-Trip public image display leases

U03-D16g connects the D16f cache to the explicitly qualified saved Plan, through the existing validated complete-envelope projection. Ordinary/hosted cold-read admission, complete metadata v2 capabilities and the original fifteen-minute private-view lifetime are unchanged. This is a read-only image component, not whole-Trip preparation.

## Projection and identity

`createPublicVariantImages` accepts an already admitted complete read, independently obtains its exact source and verified Trip binding, and allows only asset/recipe/role/URL tuples in that envelope's variant manifest. The normalized location projection validates a ready v1 hero before requesting its display URL. Repeated visits reference the same location image. The canonical domain `thumb_url`, `hero_url`, source relationships, original URLs, identity bindings, ordering, notes and immutable envelope are retained.

Only the cache's `read` operation is called. There is no fetch, automatic capture, transformation, signing, original download or private-file fallback. A missing, expired, corrupt, denied or unavailable public cache becomes the existing null-image placeholder. A ready receipt must still match the exact source, path, asset, role and recipe. The cache has independently checked digest, byte bounds, dimensions and expiry. Blob URLs are transient display values, never persisted into complete snapshots, domain URLs, native databases or commands.

## Native consumers

A dependency-free `repo/placeImageLease` port registers exact live URLs and a handler for the admitted native Trip binding. The map photo helpers, marker allowlists, marker thumbnail hook and shared avatar honor those values, including a deliberate null. This prevents stale coordinate/provider thumbnails from replacing a saved image or placeholder. Unregistered ordinary views and other Trips retain native provider behavior. No generic Blob prefix, provider URL, uploaded image or data URL gains saved-image authority.

These are narrowly documented source adapter changes. The twelve protected native layouts remain byte-identical to the accepted upstream target. No markup, style, placement, navigation, feature flag or category behavior is changed by this packet. Native details display the same checked hero; additional gallery slides and View original are not covered by this one-image contract.

## Lifetime and refusal

The adapter checks the original read fence across every awaited cache operation and URL mint. It watches actor/session end, reconnect, private expiry and read retirement. Disposal cancels work, unregisters the display handler and revokes only URLs owned by this adapter. Late reads cannot publish into a retired view; old cleanup cannot unregister or revoke another owner's URLs. Router close, projection failure and explicit dispose release leases.

An explicit authority refusal during protected publication permanently ends that particular complete-read lease. Deliberate cache ownership/generation failures and saved-reader original-work/expiry/envelope mismatches have typed refusal errors. A storage/I/O or publication-callback failure still rejects but is not reclassified as known access denial; no automatic retry or replay is added. Recovering an import/queue blocker cannot silently revive it. The existing lifetime watchers then release the image/Trip view. This does not add continuous raw IndexedDB tamper detection: out-of-band writes require an actual guarded read before that refusal is known. Original commands, imports and File bytes are preserved without replay, adoption or mutation.

Public cache retention is separate from private Trip authority. A seven-day public receipt cannot extend the private view, authenticate a member or assert whole-Trip readiness. Public bytes may survive logout while private complete generations and display leases retire.

## Qualification and limits

Desktop and phone-layout Chromium exercise the actual compiled App, SDK/TOTP and service worker in the marked disposable local project. The explicit test-only driver calls the real cache capture implementation with descriptors from the real accepted envelope. A loopback proxy supplies synthetic 2×3 WebP responses at exact fixture object paths, including worker requests. This proves byte/display integration, not hosted Storage bucket/RLS access, physical iOS/Safari, production quota usage or private-document readiness.

The test driver is excluded from standard, ordinary and source-alias builds. Tests observe actual object URL creation/revocation and native decoding, leave the serialized generation unchanged, preserve original work and deny transformation attempts before dispatch. No test-only successful cache or SDK replacement is used.

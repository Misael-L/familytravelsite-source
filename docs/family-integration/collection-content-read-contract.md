# U04-F5c3 — Collection content read/observation contract

Implementation boundary: accepted schema139; additive read routines only. Native handlers/hooks, nine lifecycle/context/outcome APIs, current edit/transfer/removal gates and all existing schema facts stay unchanged. This is a prerequisite for the coordinated native reader/writer cutover, not feature activation.

## Native audit

Native `shared/src/collection/collection.schema.ts` uses numeric Collection/item/category IDs and optional description/notes/address/contact/image fields. The Family ID registry remains the eventual UUID/numeric boundary. Native membership is `{saved,lists:[{collection_id,name,color,place_id,status,can_edit}]}`. The current Family handler instead name-matches an unbounded legacy projection and returns `{collections}`; native hooks also convert failed reads to empty membership. Neither can be reused as evidence that the new API is wired. Four transfer refusals and item-removal refusal remain intact. Unsupported labels, ratings, prices, currencies, links and provider IDs must not be fabricated.

## Public signatures and response bounds

1. `get_family_collection_page_v1(p_collection_id uuid,p_state text DEFAULT 'active',p_limit integer DEFAULT 50,p_cursor jsonb DEFAULT NULL) RETURNS jsonb`. State exactly active/archived, nonnull limit1..100, response <=2MiB. Root currently visible in that explicit state is required. Return `{version:1,scope,collection,content_revision,items,next_cursor}`. Collection combines existing checked root metadata with name/description/color/order/cover resolution. Items ordered `(sort_order,id)`; lookahead limit+1, no offsets. Cursor exactly `{version:1,collection_id,state,revision,content_revision,lifecycle_revision,sort_order,id}`. All integers finite/canonical and root-bound; last item must exist in the authorized page. Revisions must still match or PT409. No hidden/truncated success. Source projections are read at each page; this cursor freezes Collection revisions, not an external catalog-wide historical snapshot.
2. `get_family_collection_editor_v1(p_collection_id uuid,p_item_id uuid,p_state text DEFAULT 'active') RETURNS jsonb`. Same root rules, active item, <=256KiB. Return root/scope/content_revision plus one full item and `{version:1,collection_revision,content_revision,lifecycle_revision,item_revision,item_digest,source_digest}` observation. Digest is SHA256 of exact projected item (including mode/source facts/media). It is not a save token or new write permission; the later writer must re-observe canonical facts transactionally. Revisions/digests are non-lossy JSON integers/text; future adapters must reject unsafe JavaScript integer ranges.
3. `get_family_collection_membership_v1(p_family_id uuid,p_identity jsonb) RETURNS jsonb`. Exact identity is `{kind:'place'|'food'|'hotel'|'experience',id:uuid}`, `{trip_id:uuid,location_id:uuid}`, or explicitly owned `{collection_id:uuid,item_id:uuid}` for an existing manual item. No names, coordinates, provider keys or visit IDs. Canonical and Trip sources require current source permission as well as Family/Collection read authority. Trip location must be active, belong to that Family/Trip, and resolves to its exact catalog identity. Repeated visits to one saved location have identical membership. A manual Trip location has no recorded cross-library origin yet and returns0A000, not a false empty result. Manual Collection identity matches that exact owned item only; cross-list manual provenance awaits the transfer contract. Return `{version:1,identity,source_observation,saved,lists}`. Lists are current visible nontrashed roots with active matching items, sorted list order/id/item id, including explicitly marked readable archived roots (can_edit=false). Complete maximum200 matching lists and2MiB; excess54000. Future adapter maps item_id to native place_id; no direct handler activation here.

## Item and source semantics

Each item returns checked metadata plus saved name/notes, `content_mode`, `content`, `source_observation`, `geography`, category, cover resolution and native location compatibility. Snapshot content uses every child NULL/empty literally and saved name literally. Reference name inherits only when saved name is NULL; description/address/contact/own coordinates come from the typed catalog source. Personal notes always come only from list_items.notes. No child description/notes duplication. All nine kinds remain represented; country/airport/airline/guide are typed references explicitly incompatible with native location transfer, never silently omitted or assigned city coordinates.

Source projection reuses the accepted Trip catalog projection for the four location kinds with an empty override row; preserves typed source, own coordinates, country/context/timezone/type and archived status. SHA256 covers canonical source row plus projected geography/content, so same-item source edits change the observation. Nonlocation kinds retain their typed name/description/geography/own available coordinates but no invented location compatibility or financial defaults. Missing/inaccessible source refuses; no fake empty read. Manual has no catalog source digest.

Media resolution never exposes original URLs, signed URLs, bucket paths or automatic originals. For an authorized image ID the existing `catalog_media_variants_for_assets(...,'v1')` boundary supplies only ready variants; only ordinary HTTPS `/storage/v1/object/public/catalog/variants/v1/...webp` URLs are admitted. Public not-ready is a placeholder. Family covers may retain their authorized ID but return `private_unavailable` with null URLs: no new private Storage grant or claim that those bytes load. Wrong-Family/private-scope media yields unavailable without disclosing its ID. Later private-byte cutover remains explicit.

## Authority, coherence and privileges

Public wrappers are invokers, dispatch to a narrowly granted checked private definer with empty search_path; helpers have no application EXECUTE. Require current live session, Family person/membership/private assurance and existing catalog authority. Page/editor acquire/check list root before pinning authority (reuse collection_require), then recheck before returning; all item writers already lock that root, so Collection content and revisions remain coherent. Source helper is STABLE to capture one canonical statement snapshot; observations detect subsequent source edits. Membership pins current Family authority and reads a complete bounded result; it grants no source or destination writes. No new table privileges or RLS relaxations.

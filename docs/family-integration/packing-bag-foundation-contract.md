## Relational ownership and lifecycle

Reuse `public.packing_bags`, `public.packing_bag_members`, the composite same-Trip item reference and `family_auth.packing_command_receipts`. No new table or parallel receipt namespace. Bags are owned by a Trip; carriers confer no item privacy or mutation authority. Existing visible-item-plus-direct permission remains unchanged. Private-inclusive totals remain intentional shared aggregates, without hidden item IDs, names or unit details and without a statistical inference-resistance claim.

Bag columns add server-managed positive bigint `revision` default1 and paired finite `deleted_at`/`deleted_by_person_id`. The actor FK is restrictive and same-Family provenance is validated. Identity/Trip/creation timestamp are immutable. Physical deletion is refused. Bag and carrier changes advance bag and collection revisions; multi-trigger operations may advance a counter more than once. Commands that change nothing append only their immutable receipt, with no business DML/audit/counter movement.

New or changed names use the existing packing space-trimming convention, nonempty and <=500 Unicode characters. Color is null or `#RRGGBB`; nullable integer gram limits retain1..10,000,000. Unknown fields, fractional/coerced numbers and malformed carrier UUIDs refuse. Omitted fields preserve values; explicit null clears only nullable fields. Old oversized names are retained byte-exact and do not prevent unrelated bounded updates. They are never truncated or silently repaired. Six old local fixture names were proved through upgrade and unrelated administrative updates; hosted data was not inspected.

Rank is a nonnegative integer, ties permitted and ordered by `(sort_order,id)`. Creation allocates the next active rank under lock and refuses integer overflow. Active bags are bounded at2,000 per Trip; paginated Trash does not consume that quota. Restore rechecks capacity. Add only the Trash keyset index and partial actor-reference index; existing Trip/order/member/item indexes are reused.

Trash is supported only when **no live item**, including an invisible personal item, references the bag. It returns a generic dependency conflict without hidden counts/content. It retains old item Trash and carrier links. Bag restore revives no item. A dependent item or complete category batch must wait until its bag is explicitly restored. A universal item transition trigger applies this to old item create/update/restore, bound category creation/moves and batch restoration, including privileged DML. Historical trashed-item references are retained. Carrier history cannot be rewritten while the bag is in Trash.

## Strict SQL API

Public functions are invokers with empty search paths and authenticated-only EXECUTE. Restricted private definers repeat current Family/Trip/Person/assurance checks. Direct bag/member DML remains revoked for browser and service roles. Restrictive active-bag and active-parent carrier policies cannot be widened by permissive policies; no recursive RLS dependency is introduced.

- `get_family_trip_packing_bags_v1(p_trip_id uuid)` returns `{version:1,kind:'packing-bag-snapshot',scope,collection_revision,packing,bags,people}`. `packing` is the **unchanged legacy v1 shape** with active bags only. `bags` is an array of full bag observations, ordered by rank/UUID. `people` is UUID-sorted `{id,display_name,eligible}` for current travelers and referenced historical carriers of active bags. Do not assume this new three-field roster is the older category roster's four-field shape.
- `get_family_trip_packing_bag_v1(p_trip_id uuid,p_bag_id uuid,p_include_deleted boolean DEFAULT false)` returns `{version:1,kind:'packing-bag-observation',scope,collection_revision,bag,member_person_ids}`. `bag` explicitly projects its eight old stored columns plus the three new fields; future table columns cannot silently change this versioned API. Member IDs are sorted/unique. Missing/foreign/unavailable state refuses; it is not an empty success. `include_deleted=true` permits a deleted observation and does not grant writes.
- `list_family_trip_packing_bag_trash_v1(p_trip_id uuid,p_limit integer DEFAULT50,p_before_deleted_at timestamptz DEFAULTNULL,p_before_id uuid DEFAULTNULL)` returns `{version:1,kind:'packing-bag-trash',scope,collection_revision,bags,next_cursor}`. Each row is a full observation. Limit1..100; paired finite cursor; exact microseconds; descending `(deleted_at,id)`, including tied timestamps. Never use copied/torn pages as current restore authority.
- `execute_family_trip_packing_bag_v1(p_trip_id uuid,p_operation_id uuid,p_scope jsonb,p_action text,p_target_id uuid,p_expected_revision bigint,p_expected_collection_revision bigint,p_observed jsonb,p_values jsonb)` returns `{version:1,kind:'packing-bag',trip_id,operation_id,scope,action,target_id,values,collection_revision,changed,bag,member_person_ids}`. `changed` is boolean. A result is an original operation proof, never a current read publication.
- `get_family_trip_packing_bag_receipt_v1(p_trip_id uuid,p_operation_id uuid)` returns `{version:1,kind:'packing-bag',trip_id,operation_id,scope,status:'unknown'|'committed',result_redacted,result}`. Unknown is not success. Current permission denial remains denial. A root-lifecycle change can produce committed/redacted/null; a changed Person context refuses. Other stored packing domains produce22023.

Legacy snapshot bag keys remain exactly `id,trip_id,name,color,sort_order,weight_limit_grams,created_at,updated_at,member_person_ids,total_weight_grams`. The old whole-row serialization is replaced with explicit projection. Native v1 and coupled category v1/v2 parsers accept actual126 responses. Existing saved v1/v2/v3 formats and application source remain byte-exact; no saved v4 is added.

Reads use one stable database snapshot. Combining bag/category domains later requires identical full scopes/collection revisions and atomic publication. Refuse unsafe JS-number counters with54000. Full snapshots/Trash pages are bounded at8MiB; observations, complete SQL command arguments and **the complete stored receipt including before/after history** are bounded at1MiB. A final bound failure rolls back all business changes, audit, counters and receipt. ## Command actions and retry rules

Every action requires original published scope and full collection revision; target is always a UUID. Create has null row revision/observation. All other actions require the exact original full observation and positive safe row revision. Do not manufacture observations from rendered names or combine facts from different publications.

1. `bag-create`: `{name,color?,weight_limit_grams?}`; new canonical ID, empty initial carriers, server-assigned end rank. Duplicate names are distinct bags.
2. `bag-update`: nonempty subset of `{name,color,weight_limit_grams}` on an active bag. No rank, owner, privacy, revision or member fields.
3. `bag-members`: `{person_ids:[...]}` sorted unique desired IDs. Validate the entire set before any DML; current eligibility is required only for additions. Guests are valid eligible travelers. Unchanged historical carriers may remain or be removed; archived/removed/foreign/off-roster additions refuse atomically. Apply differences rather than destructive delete/reinsert. Never change item ownership/ACLs.
4. `bag-trash-empty`: `{}`, original active observation; refuse nonempty dependencies. Nonempty removal/unassignment is still unsupported.
5. `bag-restore`: `{}`, original deleted observation; any currently authorized direct actor may restore the shared Trip bag. Retain identity/content/carriers; revive no item.

Use existing Trip-recovery advisory key, Trip row, collection state, bag and deterministic child row order. Recheck current authority/scope after waits. Every effect and receipt commits together. Current direct `trip.packing.manage`, MFA, active account/Person/Family and Trip lifecycle are mandatory; propose/deny, carrier status, unrelated capabilities or a cached opening permission do not grant writes.

The existing operation key is `(trip_id,actor_user_id,operation_id)` across item/group/category/bag domains. Exact same intent returns its immutable original result before current revision checks, after current authorization/context validation. Changed intent/domain refuses409. Do not rebase, allocate a new UUID after uncertainty or infer success from unknown. The bag domain retains `category_id=NULL`; additive result constraints bind action/Trip/operation/target/bag identities. Old receipt bodies and request digests are not rewritten. A real AAL2 HTTP commit with its response body discarded is recovered and replayed exactly once.

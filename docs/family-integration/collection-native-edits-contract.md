## Displayed facts and deliberate actions

`openCollectionNativeEditor(owner, collection, item)` consumes the qualified complete read/editor facade. It binds the exact canonical observation and projects the existing native item namespace. Price/currency, image upload, provider/provenance rewrites and other unsupported fields fail before persistence. Existing normalization/SQL constraints remain authoritative. No transformations or Storage byte requests are introduced.

A form normalizes before retaining. Concurrent identical submits join one flight. A retry after an uncertain response uses the same operation; a replacement body is refused409. A terminal committed/cancelled result completes that editor; a deliberate later edit/status action must reopen and observe again. Successful edits return the fresh canonical saved item plus native projection. Errors retain the displayed initial values and pending original; they must not be rendered as empty data or successful unsaved membership.

`openCollectionNativeOrder` captures the complete coherent detail view and its content/root/lifecycle revisions. It accepts exactly that displayed set once, without omissions, duplicate IDs or foreign items, bounded by the existing100-item command contract. A larger order is explicitly unavailable, never truncated. Reordering after someone changes the list conflicts; it must not fetch a fresh version at drop/save time.

## Form retirement and recoverable originals

A child `CollectionCommandSession.scoped(assertCurrent)` inherits the original source/account/Family/person/session/Collection, deadline, verified device owner and RPC port, adding the form's lifetime check at every existing command boundary. Parent retirement also fences children. Form retirement does not retire the parent recovery owner or rewrite/delete its queue row.

If a prepare response arrives after the form closes or is superseded, the child fails before dispatching execute. If execution already reached the server, retirement cannot undo that server transaction; it suppresses later publication/acknowledgement so parent recovery can discover the true result. Parent Check/Retry/Cancel keeps the existing permission/current-session and original-identity requirements. Do not promise that closing a form cancels already dispatched work. Never bypass the parent recovery boundary or export/logout guards.

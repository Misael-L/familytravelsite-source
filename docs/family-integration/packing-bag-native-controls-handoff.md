## Release blockers still open

1. A non-restore bag command refused by the server remains retained under the existing protocol. In particular, a hidden zero-weight occupant can refuse Trash after the public projection looked empty. Preserving that intent is safe, but the existing terminal API only cancels restore actions; it cannot yet resolve every refused create/update/members/Trash operation. No generic queue deletion workaround is authorized. The action remains under a local-only qualification gate; this is a blocker for broad activation.
2. The new fresh-replacement button is currently discovered from the active confirmation component's settled state. The archive survives reload/logout and remains exportable, but discovery of a new replacement after that component remounts is not yet qualified. A durable, authenticated archived-original chooser needs testing; do not imply this UI gap is solved by archive preservation alone.

These are the immediate [D2c3 recovery-completion packet](packing-bag-recovery-completion-packet.md), ahead of templates/sharing or hosted rollout. It must preserve old restore semantics and avoid adding terminal outcomes by client assertion. This handoff qualifies the exercised native path, not the complete U04 milestone or production readiness.

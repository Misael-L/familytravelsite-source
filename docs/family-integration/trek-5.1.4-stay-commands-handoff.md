## Exact interface and ownership

The four authenticated command RPCs are save_family_stay_v1, set_family_stay_booking_link_v1, trash_family_stay_v1 and restore_family_stay_v1, using the signatures from the parent design. Save creates with a new caller-generated stay UUID or patches an observed existing stay. Repeated intentional stays have new entity/operation UUIDs; identical retries reuse the original body and return one stable acknowledgement. No hotel/date deduplication or automatic provider booking/stop creation is performed. Links connect only existing same-Trip hotel bookings and saved hotel/manual lodging; known catalog hotel identities must agree.

A new get_family_stay_command_context_v1(p_trip_id uuid,p_stay_id uuid,p_location_id uuid default null,p_reservation_id uuid default null) provides authoritative create/edit admission. Its version 1 scope is exactly {version:1,layer:'published',trip_id,family_id,user_id,person_id,session_id}. **The required session_id is a deliberate stay-only refinement** of the older six-field scope; existing contracts were not changed. The observation is exactly {trip_revision,stay,candidate_location,candidate_booking}; stay is the complete existing projection or JSON null for a new identity. Candidate projections bind selected target rows, so refreshing only the Trip revision cannot hide a changed stay/location/booking.

The Save patch is restricted to location_id, arrival_date, departure_date, check_in_time, check_in_window_end, check_out_time, check_in_window_end_day_offset, time_zone and notes. Creation requires location and both civil dates. Omitted fields remain intact; explicit null clears only nullable facts. Dates use finite ISO dates 0001–9999, local clocks use HH:MM[:SS] without offset/fraction, offset is integer 0/1, notes are bounded to 20,000 UTF-8 bytes and zones use the existing named-zone validator. Same-day/midnight/overnight/off-calendar planning remains explicit. No provider instants, booking metadata, native IDs, ownership or catalog facts are writable through that patch.

Current session/AAL/Family/person/active-Trip and Direct trip.schedule.manage are required. Changing an association additionally requires Direct trip.reservations.manage. Propose/deny and private-layer requests remain refused; there is no published fallback. Trip recovery advisory/row locks precede sorted child locks. Auth-session/membership locks protect current admission; **fresh authority checks run after metadata locks and after all child locks**, including current expiry and policy/person/scope checks. A client GUC never authorizes a bypass.

One append-only private table, family_auth.stay_command_receipts, serves as operation receipt and before/after history; a second redundant image store is unnecessary. It has a shared (trip_id,actor_user_id,operation_id) namespace across all actions, a unique server sequence, exact body digest, original session/actor, immutable before/after images, changed flag and stable result. Composite same-Trip/Family/stay/person FKs and restrictive deletion preserve ownership. Session IDs intentionally have no auth.sessions FK: logout/session cleanup must not erase or block history. RLS is enabled; PUBLIC/anon/authenticated/service_role receive no table/sequence rights. Private helper EXECUTE is revoked; only the six public entry points are granted to authenticated, with fixed empty search paths and internal authorization.

Each result is an immutable **acknowledgement**, with operation/action/identity, changed flag, committed stay/Trip revisions, event sequence and timestamp. read_current_required=true means a receipt is not replacement content. A historical retry rechecks current authority and the original body/session, then returns its old acknowledgement without applying it again. A new valid Auth session cannot silently rebind and replay an old operation. Unknown outcomes after logout need the later queue/outcome contract; do not generate a new operation ID to bypass this rule.

get_family_stay_history_v1(p_trip_id uuid,p_stay_id uuid,p_before_sequence bigint default null,p_limit integer default 50) provides keyset pages 1–100, has_more/next_before_sequence and an 8 MiB output limit. It returns action, sequence, operation, actor person, time, changed and before/after images, not session IDs/request digests/internal results. Trashed-stay history requires recovery authority. Family portable export adds trip_stay_history under the existing active-Trip scope using that safe content projection. Raw receipt bindings/digests remain in SQL backups rather than portable content export.

## Recovery, conflicts and measured results

A stay/link/revision/history/receipt change is one transaction. Failed constraints or late receipt insertion roll back everything; sequence gaps from rolled-back transactions are normal. No-op saves/links/repeated Trash/restore leave content and Trip/stay revisions unchanged while recording a new accepted operation. Parent Trip Trash blocks new commands and old receipt replay; parent restore retains every identity. Stay Trash retains its booking/link/notes, and restore validates the original lodging/booking. Unlink never deletes either content record, a saved location, catalog record or file. Purge stays unavailable. Confirmed booking timing and transport endpoint edits remain separate qualified-command work.

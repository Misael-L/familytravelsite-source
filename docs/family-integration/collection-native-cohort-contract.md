# C5b2c2 — native Collection cohort contract

Website scope only, schema143. This completes the supported reader/form/picker/recovery cohort built on C1–C5b2c1; it does not authorize a production database change, deployment, source-adoption repin, remote publication or main merge.

## Ownership and authorization

One controller belongs to the verified backend source, Auth user/session, Family, linked Person and repository generation. Every asynchronous read, command, callback and image belongs to that owner. A→B→A is a new lifetime. Each native edit/add/order/picker owns its displayed observation; retirement stops undispatched work and retains the parent's original for explicit recovery. Canonical Family UUIDs remain browser URLs; numeric keys are presentation-only namespaces. Collection/Trip/catalog identities are never inferred from a name, provider ID, address or coordinates. Both native membership consumers use the canonical contract; unavailable/denied is not an unsaved success.

Family permissions come from can_edit_items/can_admin/is_owner plus server authorization, including source/session checks. Unsupported nullable owners remain visible as retained unavailable entries. No user_metadata, fabricated member role, fake parent or replacement visit is authority. Root/item removal uses the observed C1 commands with reachable selected-original Restore on both shells; raw native DELETE and the four unqualified transfer routes remain refused.

## Ordinary native forms

Country, city, food, hotel, experience, airport, airline, guide and manual entries retain canonical sidecars, notes distinct from descriptions, categories/contacts and geographic context. Nonlocation entities have no substituted city coordinates. Shared catalog references display current catalog information. Snapshots/manual items own independent location detail. The native form's unchanged display defaults are omitted before save; references permit changed name/personal notes, and changed location detail requires an explicit snapshot first. This avoids silently materializing or writing catalog descriptions back as personal notes. An unchanged native save still uses the observed server no-op contract rather than fabricating a success.

Manual/reference/snapshot creation, explicit materialization, item fields, status, complete ordering and lifecycle commands use the existing immutable format3 request/original queue. Same-form retries retain the original UUID/body/observation; conflicts and changed bodies do not acquire a fresh observation. Cancellation and unknown outcomes use the existing V2 preparation protocol. Native refreshes must not dispatch generic replay or drop retained work. Unsupported populated fields are refused; only native empty links/labels defaults are normalized away.

Library metadata, list covers/order/sharing/labels/ratings/import/export/private bytes and Trip transfers remain outside this cohort. Controls explain unavailability or remain disabled. Tours stays disabled. No backend carryover file, schema, billing setting or image transformation is changed.

## Source activation gate

The pre-existing native retained-write source policy is still qualified only for its bounded loopback aliases with local-v1. This packet must not widen that policy. Ordinary sources without a matching verified source-owned queue show an explicit read-only Collection state; editing, removal and picker toggles cannot pretend to work there. The local browser command proof uses the existing qualified ordinary build configuration. A separate ordinary Supabase-shaped synthetic-source build proves read-only behavior and stored images with external traffic intercepted. Both use real isolated Auth/REST/database responses, no product state injection or fabricated capability. Broader source activation remains a separate release-readiness prerequisite, not evidence that hosted writes have been enabled.

## Stored images

A Collection display lease carries distinct ready stored thumb/hero URLs for its original view. Small avatars/markers request thumbs; full detail requests heroes. A missing hero does not enlarge a thumb. Retired views and missing variants stay handled placeholders; native provider lookups cannot replace them. No catalog /render/image/ request, automatic original fallback, regeneration, Storage upload or transformation is allowed. Explicit originals and other media features outside this cohort are unchanged.

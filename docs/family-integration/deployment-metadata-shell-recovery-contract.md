# U03-D16m — public release identity and startup recovery contract

The web build emits `/family-build.json` after entry rendering. `family.build.v1` has exactly `format`, `version` and `entry`; entry has exactly `path`, `bytes`, `sha256`. Version is a native-compatible 1–64 character release tag. Path is a root-relative content-hashed `/assets/index-….js`; body size is 1–8 MiB and digest is lowercase SHA-256. The production release opt-in rejects anything outside `family-YYYY.MM.DD.N[-rc.K]`. Local/development builds may retain their existing package-version default. Metadata identifies public static files only; it is not a signature, backend health, fresh membership, Auth/MFA, permission, database revision or offline readiness.

The classic `public/family-build-contract.js` is the shared parser/reader for the preboot guard and Family observer. It loads before the guard/main. Reads use captured native same-origin fetch, anonymous credentials, `no-store`, a changing non-precache query and redirect refusal. The complete observation—including streamed body reads and optional entry digest—is limited to three seconds. Descriptor decoded size is at most 8 KiB; malformed/future/extra keys, invalid paths, status/MIME, redirects, truncation, size overflow, cancellation and missing digest capability refuse. For compressed responses, byte checks apply to the browser's decoded stream rather than compressed Content-Length. Entry verification requires exact decoded size, JavaScript MIME and SHA-256. No private metadata or Storage object is involved.

Vite explicitly excludes the descriptor from precache and navigation fallback; no runtime route caches this JSON. `public/_headers` marks it no-store on Cloudflare static hosting. The generated worker is inspected and actual CacheStorage keys checked in browser acceptance. This metadata is served by the app host, not Supabase. The classic contract itself remains a normal public shell asset, available to the preboot guard when the entry is corrupt. Recovery cannot repair a guard/contract script that itself never executes.

Family bootstrap captures native fetch before installing API adapters, installs the release observer and injects its initial `readVersion` through the existing scoped handler factory. Unavailable observations retain the running bundle's label; they do not fabricate a remote report. Subsequent actual controller-change, online, focus and visibility events coalesce behind one pending read with a minimum one-second cadence; visible/online polling is at most once per minute. Hidden/offline triggers are quiet. Source changes, cancellation, disposal and stale async results cannot publish a prior source observation. The observer does not set the first native report before App consumes initial config. It uses the existing native store/notice/handover and leaves native markup unchanged. A page in use is not automatically reloaded by these observations.

The classic guard retains bounded real-health automatic recovery where available. The static-host route is the existing explicit **Try again** action: obtain live public metadata, fetch the entry past precache, check bounded decoded bytes/MIME/digest, then retire only the controller's own registration and exact `workbox-precache-v2-<scope>` public shell. Scope/origin/controller script must agree. Native postboot `dropAppShell` uses the same restricted cleanup. Other-app precaches, map/fonts/uploads, all IndexedDB databases, owner markers, original queue/import rows, media identities and private bytes remain intact. A disposed/recovered entry or newer failure epoch fences late results; duplicate clicks are suppressed. Invalid proof can retry the document but never delete cache state. Without a session marker there is no automatic recovery loop; explicit user retry remains available. Unregistering a worker can invalidate its Web Push subscription; re-enablement may be needed, as with existing shell recovery.

A descriptor validates the public entry, not every server dependency, a running private session or the entire release's functional health. A consistently broken remote dependency still produces a bounded fallback; no private data is discarded to hide it. A previously shipped bundle without release-discovery code cannot gain the observer without loading updated code. Actual A/B acceptance therefore uses two distinct Family release IDs built with this repair and the same underlying TREK 5.1.2 source baseline.

No source pin, permission, database/schema, SDK/dependency, production/preview/hosting/billing, download capability, transformation quota, backup/media or ignored ETL setting is changed. Read `release-build.md` for the later release procedure; this packet does not deploy.

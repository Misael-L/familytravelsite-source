# U04-B native packing item controls contract

Scope: the existing `codex/trek-v5.1.2-family-reconcile` application and its explicitly installed Family planner. This completes item-control wiring above migration119 and the previously qualified observed packing SQL/SDK/queue and cold-recovery contracts. It does not implement aggregate packing writers or authorize a hosted release. Existing task, geography, trip, media and source-provenance identities remain intact.

## Original observations and native behavior

The packing slice enters the installed port before optimistic state, legacy repository/cache writes or HTTP effects. A branded draft origin owns the original port, Trip and target; forged, detached, foreign or missing observations refuse. Rendered rows own checkbox/partial-count commands; the original complete set owns reorder. No slice borrows a later store revision to make a stale operation succeed. Outside the explicit Family port, ordinary TREK argument shapes and behavior remain intact.

A verified warm reload of the same private Trip/actor/source/layer preserves packing originals; cold or scope-changing loads still retire them. Preserving an original never rebases its row revision.

An opened create, inline rename, focused quantity/weight field, selection picker or phone sheet binds one original actor/source/Trip/layer/session and row revision. A draft freezes one logical payload, target and operation. Concurrent identical saves coalesce; a changed unresolved retry refuses. Deliberately starting a subsequent create allocates another identity. A filled category placeholder updates its original item; subsequent creates are independent. Last-item Trash removes that item and never runs the native placeholder-maintenance update loop.

Typed values survive row refreshes and slow replies. A temporary permission pause disables Family checkboxes and the phone Save button, and keeps an already-open draft visible and read-only; it is not new mutation authority. Numeric response-loss retries confirm the same original operation even if a later canonical publication already displays the submitted value. Closed, unmounted, retired-source/actor/layer/session callbacks cannot close a newer form, show a late toast or write its state. A completed origin is not reusable for another mutation. Shared and My list have separately owned composer maps; callbacks from a retired view cannot borrow the new view's composer or change its visibility.

## Permissions, publication and paused reads

`packing_edit` availability requires the installed packing port and current Family authorization; `trip.packing.manage` must be **direct**, in either itinerary layer. A draft/proposal capability never becomes packing mutation authority. Offline saved sessions remain read-only and raw Family writer endpoints remain refused.

Current state comes only from canonical reads. Historical acknowledgements and receipts prove an original command; they are never projected as current items. Packing state and owned ancillary state update coherently before subscribers run. Bags/assignees subscribe to that owner, including empty replacements, and private-inclusive weights come from authoritative totals rather than visible-item arithmetic. The native bag/weight feature uses this qualified publication within the Family packing panel; global add-on settings and ordinary TREK behavior are unchanged.

A background planner refresh may encounter a pending original and pause authority. Once a packing original is acknowledged and canonical packing is read, the exclusive queue lease is released. If the planner boundary is still paused, the composition obtains a fresh guarded planner read and governance validation. It does not grant authority from an acknowledgement, ignore pending work, hold the exclusive lease across another guarded read, or restore a stale permission controller. Refused revalidation remains refused. Once the original is acknowledged and its canonical packing result is read, a competing ancillary refresh failure does not turn that saved operation back into an unresolved form save. The guarded reader retains its problem/newer publication; no write authority is fabricated, and subsequent writes remain subject to current authorization. A real boundary regression and actual desktop/phone acceptance cover this handoff.

## Trash and unsupported actions

Desktop and phone expose native-compatible Packing Trash, Restore and retained-operation confirmation. Each fetched page keeps its exact original page/row observation. Concatenated display rows never manufacture a Restore origin. Restore refreshes ownership; failed follow-up reads invalidate displayed pages while retaining unresolved queue work. Unknown receipts remain unchanged; committed/redacted receipts follow the existing cold/warm recovery rules.

The broader native packing permission does not enable category rename/delete/check-all/clear, import, template application, sharing, contributors, clone or bag management. Those controls have separate group gates and their callbacks refuse **before the first effect**, including parsing/FileReader, optimistic state, item loops and raw API calls. Qualified individual item category/bag assignment and complete observed item reordering remain item commands. Category creation is one explicitly bound placeholder create, not an aggregate loop.

## Qualification and release boundary

Acceptance uses actual native consumers through handler → port → slice/form → retained queue → canonical publication. It covers stale forms/sets, slow replies, Enter+blur, immutable retries, deliberate repeat creates, privacy and totals, empty replacement, source/actor/layer/logout retirement, owned Trash pagination, paused authority and unsupported first effects. Extra SDK/password/TOTP/PostgREST/RLS checks and bounded actual-App/generated-worker desktop/phone walks use only new synthetic Families/Trips on the marked disposable API55331/DB55332. The browser proxy blocks hosted destinations and image transformations. These are Chromium phone-layout tests, not physical iOS acceptance.

The fresh complete suite preserves all historical assertion/status multiplicities except one explicitly obsolete “packing remains unavailable” boundary case. That case is replaced by qualified direct/deny/propose/retired authority checks; no authorization assertion or baseline is weakened. All other old cases and the existing93 pending statuses are retained. Diagnostic failures are not passing evidence. Only the tested committed application objects enter the explicit per-path source manifest, followed by actual guards and their tests.

No main merge, push, production/preview deployment, hosted migration/settings/billing, dependency upgrade, image transformation/backfill, original backup/media or ignored ETL operation is part of this packet. Independent database-plus-files restore, off-device copies and incremental capture remain separate, unproved work.

## Implemented behavior

The native accommodation repository uses an exclusively installed qualified writer port. Desktop and phone edit-open callbacks pin the exact original accommodation object. Its canonical observation is held privately, outside request/native row payloads, with source, actor, Auth session, Family/person, Trip, layer, identity registry and generation checks. A background replacement cannot silently rebind an already-open edit. Ordinary upstream repository calls retain their original argument shape when the port is absent.

A strict adapter maps existing saved lodging and original Trip-day identities to canonical civil dates. Omission, explicit clearing and genuine midnight remain different. Named time zones are inherited unless a more expressive separately qualified command handles them. Unsupported overnight/subminute fields and changed booking confirmation refuse before mutation. Stay clock/date/notes changes do not rewrite linked booking instants, microseconds or independently owned booking data.

The original observed command retains one immutable identity, body and operation ID under the existing exclusive queue lock. Double-submit/retry cannot create another operation. Staged imports and late source/session switches refuse before retaining/sending. A confirmed acknowledgement is never published as a current row: the whole coherent core and authorized ancillary cohort must be read again first. If that hydration fails, retry reads the confirmed result rather than performing another save.

The generated phone check also exposed an initial-publication mismatch: the capture opened before the Trip was visible, then the original-intent fence mistook its accepted publication for navigation. That intent fence now requires the exact captured target Trip after publication; the original read fence remains strict. Cold/null and prior-Trip handovers, foreign selection and return-to-null refusals are regression tested, including an actual signed cold publication save.

The signed offline test exposed a real distinction: the existing capture/read fence correctly refuses offline reads, but also prevented retaining an edit from an already accepted online view. A separate original-intent fence retains every identity/generation check while allowing only that original local intent to be queued offline. Read/capture fences still require online access; cold saved trips remain read-only. Actual SQL authorization, expected observations and current permissions are rechecked on retry.

Startup recovery does not depend on a planner snapshot whose publication is blocked by pending work. It compares the exact retained row, including metadata/status, before and after asynchronous operations. The original session can reconcile or retry that original command. A new valid session can inspect/cancel unknown intent; it cannot replay or rebind the previous session's write. Source/account/Trip/layer changes, competing work and recovery view disposal retain unresolved intent instead of silently discarding it.

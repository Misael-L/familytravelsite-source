## Single canonical core, explicit format

`family.offline-trip.v4` / `family-web/complete-trip-v4` stores `data.core` (the entire checked booking/stay-v2 envelope, including its single-MVCC published planner) exactly once, plus variant descriptors, header, task packet, packing packet/category-identity-v2 snapshot and companions. There is no independent stored `data.planner` or `data.booking` copy. Compatibility views are derived temporarily for validation/projection, not persisted as another editable source of truth. Independent ancillary modules retain their actual revision/collection/lifecycle vector and unversioned evidence; they are not represented as part of the SQL core's MVCC snapshot.

The strict serializer and parser are paired. They verify source/user/Family/person/Trip/published ownership, persisted owner/Trip generations, exact canonical facts, calendar/revision/relationship consistency, active and retained stay identity bindings, per-component manifests, the complete digest, media safety and 16MiB aggregate bound. Existing planner/core/ancillary bounds still apply. Unknown fields cannot be silently stripped; invalid raw facts, partial content, altered bindings/manifests, future versions, mixed packing generations, foreign identities and unsafe image references fail the whole observation.

All active/retained stay UUIDs have the existing **stay** namespace, distinct from lodging/place, reservation, geographic context and day. Original null versus true midnight, named zones, exact timestamp strings/microseconds, repeats, retained-link privacy and off-calendar/overnight facts survive. V4 can faithfully preserve a canonical stay that upstream Accommodation cannot render; it does not silently omit it or claim native compatibility. `coldRead` and `coherentStays` are true, while writes/tags/mediaBytes/nativeStays remain false. Canonical v2's native read/write/confirmed-timing flags remain false.

Existing v1/v2/v3 schemas, fields, producers, capability meaning and serialized fingerprints remain exact. Existing validators/helpers are exported for v4 reuse without widening old parse acceptance. Older parsers refuse v4; v4 does not relabel or upgrade old cached data. A saved envelope is private content, never current online authorization.

## Capture, storage and original-owner lifetime

`createCoherentTripCapture` is an explicit producer, not an installed native port. It calls the actual B2b3b1 reader once (or a passed qualified dispatcher reader), freezes its own copy of that canonical core, then accepts independently validated ancillary modules. The ancillary loader cannot replace or mutate the retained core. It must honor the provided fence and its own actual resource authorization. The current tests use representative synthetic ancillary packets; this packet **does not** claim all ancillary packets were fetched together through the real application bundle. That is the next integration task.

Source, account/Auth session, Family/person, selected Trip, published layer, registry, request abort, repository invalidation and original local work are fenced across the complete capture. No raw-table/service fallback or cache substitution occurs on offline/missing/denied API reads. Cache persistence uses the existing queue/owner/Trip guarded transaction and compare-and-swap head. It adds one immutable complete generation and advances the head together, removing only its own prior generation. A late competing capture cannot overwrite a newer head. No native store, ordinary partial-planner row, accommodation table or command queue is published by capture.

A new adversarial test reproduced a real narrow race: after a successful cache commit, the final async session check could fail while leaving that newly written head behind. The repaired path retracts **only that exact committed generation** in an independent compare-and-swap cleanup. Newer heads and foreign/future ownership remain protected. It does not place network/Auth waits inside an IndexedDB transaction. A known online access denial before persistence still evicts only the original lease. Storage/cleanup failures remain failures, not proof of successful retraction.

The shared cache row type explicitly retains either legacy or v4 values; it never interprets one as another. `openCoherentTripRead` uses the same original-owner/queue/import/head/body/clock fencing as the old cold reader, with the dedicated v4 parser. It observes an existing persisted head without creating/renewing authority. Clock rollback/expiry, changed same-ID body, head replacement, owner retirement, queue/local work, logout/source/Family change and returning online refuse publication. It publishes only through the caller's checked callback and installs no native/read-write UI ports.

Both new capture and cold selection require `VITE_FAMILY_STAY_READ_QUALIFICATION=local-v4` **and exactly** `http://127.0.0.1:56471`. Hosted/default builds cannot admit this rehearsal. Existing offline/preparation/native flags and accepted local sources remain unchanged.

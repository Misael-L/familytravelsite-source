# U04-C3b1 — category-bound item command foundation before virtual projection

Accepted locally on 12 November 2026; see [actual acceptance/handoff](packing-category-bound-item-handoff.md).

Prerequisite: accepted C3a local123 schema, strict lifecycle guard, final source and frozen200-case receipt. Native presentation/runtime remains qualified C2c3; no empty-card UI activation is implied. Preserve retained120,122 and123 projects and their original guards. Do not run hosted SQL, deploy, upgrade dependencies/images, change billing, transform media, rewrite backups or inspect/modify ignored ETL.

## Why this packet comes first

C3a creates, retains, dismisses and restores empty category metadata. Legacy item v1 create/move still resolves raw category **names**. A native placeholder must not use that path: after a concurrent rename it could create a different category. Before SDK/projection work, bind adding/moving an actual item to a category UUID and its complete original v2 observation. Keep stored `...` content genuine; do not automatically identify it as a sentinel.

## First deliverable: exact bounded contract

Read the C3 audit, C3a contract/handoff and current item v1 request validator, execution, receipt, category link/resolve guards and both strict coupled readers. Specify a new versioned command/result/receipt discriminator for only (a) creating a real item in an existing active category and (b) moving a real active item to an existing active category. Preserve item v1 functions/shape and one shared operation namespace. No arbitrary category-ID field is added to the old JSON parser.

Require original scope, operation UUID, client item UUID for create or original item ID/revision for move, original collection revision, target category UUID and complete v2 target observation. Use the same common/own-personal authority and derive privacy/owner from the category; clients cannot independently contradict that identity. Define exact allowed create fields through the qualified v1 validator, and a move-specific schema that cannot overwrite unrelated item facts. Define provenance/recipient/contributor rules when common/personal scope changes; until those rules are specified and proved, refuse cross-owner/cross-privacy moves. A read-shared foreign personal category never grants writing authority. Do not turn an old queued name-based intent into a new category-bound intent.

Comparison and resolution happen under the existing aggregate→Trip→packing-state→category/item/assignment lock order. Recheck current authorization and Auth session after waits. Stale category name/revision/retention/order/lifecycle/provenance or collection means PT409; never silently bind a different identity or recreate a dismissed category. Exact original retries return the original committed result after current authorization; changed intent/domain conflicts. Keep known/unknown/redacted receipts distinct. Design explicit action/domain CHECK extensions and returned final item/category facts before implementation; no new ledger namespace.

New guard/rehearsal adapters only; do not redirect or weaken historical guards. Preserve existing Trip recovery, media identities, item/category assignment provenance, audits, receipt digests, raw Unicode labels, default empty raw category and same-label owner lanes. No physical deletion, implicit name merge, category reorder, nonempty-category Trash or batch restore in this packet.

Rehearse final-source empty/populated123→124, rollback and exact unrelated function/security preservation. Cover no-op move, intentional repeated items versus one retried operation, both rename/create and rename/move races, category dismissal/restore races, hidden foreign items, item/collection overflow, bag/owner/recipient context, scopes/roles/MFA/revoked/expired sessions, stale originals, late receipt failure and old domain compatibility. Run all200 C3a/inherited tests on the new guarded target, plus new cases; prior results are not substitute evidence. Keep original120/122/123 data and Storage fixtures exact. Seal sanitized source/proofs and scoped local metadata snapshots. Native authoring flags remain unchanged.

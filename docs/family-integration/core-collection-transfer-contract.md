## Required behavior to freeze before DDL

Preserve shared catalog description separately from Collection-specific notes and intentional overrides. A kept item must survive deletion/Trash of its source Trip without losing personal text or media references. Catalog identity stays typed; geography is context only. Model manual locations explicitly. Do not put whole native API payloads into an unvalidated JSON snapshot, copy temporary signed image URLs, or alias reservation/visit state into the shared catalog.

Prefer extending the real list/item domain with normalized location content and bounded provenance, rather than creating a second disconnected Collections library. Compare a location subtype/child relation against additive item fields using actual existing constraints and the eight current item kinds. Keep non-location country/airport/airline/guide items working. Produce exact reviewed SQL, types, checks, unique keys, indexes, RLS/grants, deletion/restore semantics and routine contracts before implementation. This document intentionally does not invent migration filenames or declare those decisions already complete.

A transfer from a Trip must read the canonical saved location, observe its revision and intended itinerary layer, and validate source read authority plus destination list edit authority. Client-supplied name/notes/coordinates must never bypass canonical observation or an explicit supported edit contract. Destination membership/status is an independent fact. Copy-to-Trip must check list visibility plus destination Direct/Propose/Deny, current session, Trip lifecycle and observed target revision. No implicit published-layer fallback. Missing permission is not a duplicate-success response.

Saving/copying a location to a Trip pool does not schedule a visit. Repeated visits remain independent records referencing a pool location. Reusing an existing catalog pool source must not overwrite its notes, category, coordinates or other overrides. Return an explicit existing/conflict outcome when destination content differs; never report a skipped duplicate as a successful content copy. Decide and document manual-item provenance/reuse rules before adding a uniqueness rule; names/coordinates are not safe deduplication keys.

Every mutating transfer has one immutable operation ID, exact immutable payload/observations, original source/actor/session/target scope and an owned retained outcome. A lost reply retries the original operation. A deliberate new transfer uses a new operation, without fabricating a second scheduled visit. Replays recheck current authority; historical acknowledgements do not replace a newer destination. Multi-item transfer admission is all-or-nothing unless an explicit native partial-result contract is frozen and tested; do not mutate a valid first item before rejecting a later one.

Membership needs typed exact identity and the native envelope, including editable versus readable status. Fix the query plumbing at the non-presentational data boundary; do not infer identity from display name, use ambient picker state or silently return `saved:false` after an authorization/read failure. The native hooks currently swallow membership errors, so merely throwing a backend error is insufficient to make that read state honest. Specify a coherent loading/unavailable/retry state shared by inspector, desktop and phone before reconnecting toggles. Preserve native structure and styles.
